# 系统一 · 运维知识库页面接口文档

2026-11-05。S1-K01—K04 已实现并完成独立开发 MySQL 验证。页面支持浏览、筛选、详情、新增、编辑、引用手册、上传配图与人工整理已验收维修案例。依据[需求基线第14.1节](../需求基线.md)、[系统一接口清单](系统一接口清单.md)、[接口通用约定](接口通用约定.md)和[首批接口约定](首批接口约定.md)。

## 页面操作与请求

| 操作 | 接口 | 页面行为 |
| --- | --- | --- |
| 初始化设备与类型选择 | BASE-04 `GET /api/v1/reference-data`、S1-E01 `GET /api/v1/equipment` | 类型用共享编码，设备名称旁显示档案类型标签，缺失时显示待补充。设备接口已支持服务端筛选与分页，并返回 typeCode/typeName；前端仍兼容并规范化历史整数 ID |
| 浏览、搜索、选择故障 | S1-K01 `GET /api/v1/knowledge-articles` | 更新筛选时回第一页，选择一条故障记录后进入详情 |
| 打开知识 | S1-K02 `GET /api/v1/knowledge-articles/{articleId}` | 显示正文、人工步骤、引用附件及维修来源 |
| 新增或保存编辑 | S1-K03 `POST /api/v1/knowledge-articles`、S1-K04 `PUT /api/v1/knowledge-articles/{articleId}` | 人工编辑后保存，成功采用服务端返回的详情和版本 |
| 关联及读取附件 | S1-F01/F02/F04 | 从关联对象选择已有附件，按附件ID取元数据和文件流。新增配图沿用附件模块的创建及关联约定 |
| 从维修整理案例 | S1-R02/R03、S1-K03 | 筛选已完成工单，查看详情，人工整理后保存知识 |

JSON响应沿用 `{code,message,data,timestamp}`。业务ID为字符串，版本为JSON非负整数，时间戳带 `+08:00`，业务时区为 Asia/Shanghai。下文响应字段均位于 `data`。无记录的集合返回空数组，未知的可空值返回 `null`。

## S1-K01 查询文章

请求 `GET /api/v1/knowledge-articles?equipmentId=8&category=TROUBLESHOOTING&page=1&pageSize=20`。

| 查询字段 | 类型与用途 |
| --- | --- |
| `equipmentId` | 可选，设备ID。匹配直接适用该设备的知识，以及适用该设备档案类型的知识 |
| `equipmentType` | 可选，取共享设备类型编码。匹配直接关联该类型及关联该类型设备的知识 |
| `keyword` | 可选，按去除首尾空白后的文字匹配标题、故障现象及正文 |
| `category` | 可选，使用下文分类枚举。选择故障可分别筛选常见故障或人工排查步骤，再按文章ID打开详情 |
| `page`、`pageSize` | 正整数，页码从1开始，默认20条，最大100条 |

多筛选条件取交集，设备与其类型匹配到同一篇文章时按 `articleId` 去重。排序为 `updatedAt DESC, articleId DESC`。响应为 `{items,page,pageSize,total}`。每项含 `articleId,title,category,equipmentId,equipmentType,faultPhenomenon,attachmentCount,sourceRepairOrderId,updatedAt,version`，正文和完整步骤由K02读取。空搜索结果返回200及 `items: []`，页面保留筛选并显示空结果。

## S1-K02 文章详情

路径参数 `articleId` 为字符串。返回列表摘要字段及以下内容。

| 字段 | 形式和用途 |
| --- | --- |
| `content` | 字符串或null，人工维护的正文 |
| `steps` | 有序字符串数组，按数组顺序展示人工步骤 |
| `attachmentIds` | 字符串数组，顺序用于展示，引用已有手册、文档或配图 |
| `sourceRepairOrderId` | 字符串或null，有来源的案例可通过R03打开原工单 |
| `createdAt,updatedAt,version` | 创建与更新时间、整数版本，编辑时传回版本 |

设备名称和类型标签复用设备档案、共享字典。无图片时正文正常显示。步骤直接来自选中的知识内容。文章不存在返回404。

## S1-K03 新增、S1-K04 更新

两者均传 `requestId,operatorName` 和下表内容。K03可传 `sourceRepairOrderId`，K04带 `expectedVersion` 和非空 `reason`。PUT按完整可编辑字段保存，明确清空可空值传null，清空数组传 `[]`。

| 内容字段 | 规则 |
| --- | --- |
| `title` | 非空字符串 |
| `category` | 值 `INTRODUCTION` 设备介绍、`OPERATION_MAINTENANCE` 操作保养、`COMMON_FAULT` 常见故障、`TROUBLESHOOTING` 人工排查步骤、`REPAIR_CASE` 维修案例 |
| `equipmentId,equipmentType` | 字符串或null，至少填写一项，两项都有时核对设备档案类型 |
| `faultPhenomenon` | 字符串或null，用于故障列表及搜索，故障和排查类需填写可辨识的现象 |
| `content,steps` | 字符串或null、有序字符串数组，正文或步骤至少一项有内容，人工排查类须有步骤。前端以安全文本呈现正文和步骤 |
| `attachmentIds` | 字符串数组，后端验证每个附件存在且可引用，重复ID返回字段校验错误 |
| `sourceRepairOrderId` | K03可选，仅维修案例可提供。服务器核对工单当前为 `COMPLETED`，案例范围与来源设备一致。K04沿用已保存的来源关联 |

示例新增请求如下。

```json
{
  "requestId": "b73b79a3-1ee2-4c73-b887-68b4a66240b5",
  "operatorName": "张工",
  "title": "轧机振动异常排查",
  "category": "TROUBLESHOOTING",
  "equipmentId": "8",
  "equipmentType": null,
  "faultPhenomenon": "运行时振动增大",
  "content": null,
  "steps": ["核对已记录的运行工况和振动数据", "查阅设备手册中对应的排查条目"],
  "attachmentIds": ["31"],
  "sourceRepairOrderId": null
}
```

保存成功返回K02详情和新版本。正文、范围、附件引用和变更审计在同一事务保存。编辑记录前后值、原因、经办人和时间。案例保存只写知识及其关联，工单事实由维修接口维护。同一 `requestId`、同一内容重试返回原结果，幂等重放先于版本核对。

## 附件与维修来源联调

- 选设备手册调用 F01 `GET /api/v1/attachments?ownerType=EQUIPMENT&ownerId=8&fileKind=MANUAL&page=1&pageSize=20`，选择返回的 `attachmentId`。`ownerType` 共用 `EQUIPMENT/MAINTENANCE_CONTRACT/KNOWLEDGE_ARTICLE/REPAIR_ORDER`，`fileKind` 共用 `IMAGE/MANUAL/DOCUMENT/PHOTO`。文章保存只提交附件ID，同一手册实体可关联多篇知识。
- F02 `GET /api/v1/attachments/{attachmentId}` 读取文件名、媒体类型等。F04 `GET /api/v1/attachments/{attachmentId}/content?download=true` 下载，省略下载参数按附件接口预览。成功为文件流，失败按通用错误处理。单个附件读取失败时仍显示正文，标记该附件不可用。
- 文章配图在文章已有ID后复用 F03 `POST /api/v1/attachments`。multipart 传 `requestId,operatorName,file,ownerType=KNOWLEDGE_ARTICLE,ownerId=articleId,fileKind=IMAGE`，返回 `attachmentId,version` 及附件元信息。上传在同一事务中追加 p2_knowledge_attachment、推进文章版本并留痕；上传后刷新K02读取关联及文章版本，再编辑引用集合。旧表单更新得到版本冲突，避免覆盖新图片。附件响应 version 仍为附件自身版本，不是文章版本。文件大小和媒体类型按附件模块统一校验。已有手册走引用流程。
- R02 `GET /api/v1/repair-orders?status=COMPLETED&equipmentId=8&page=1&pageSize=20` 选来源。R03 `GET /api/v1/repair-orders/{repairOrderId}` 读取设备、故障说明、维修及验收摘要，页面将可引用内容带入可编辑表单。人完成整理后调用K03。只有通过验收并处于完成态的维修单可作为来源。

## 错误处理与验收

| 场景 | 接口结果 | 页面验收 |
| --- | --- | --- |
| 非法分类、分页、空标题、范围不一致、步骤或附件ID格式错误 | 400，按通用约定返回字段错误 | 定位相应控件，保留编辑内容 |
| 文章、所选设备、来源工单或引用附件不存在 | 404，返回对应缺失对象提示 | 保留表单，提示重新选择或重读 |
| 工单仍待验收、验收未通过或状态改变 | 409 `STATE_CONFLICT` | 保留案例草稿，刷新工单来源；文章未生成 |
| 两人基于同一版本编辑 | 后到请求409 `VERSION_CONFLICT` | 保留编辑内容并提示读取最新版本，用户核对后以新请求重新保存 |
| 请求超时重试 | 同请求同内容重放原结果，异内容409 `IDEMPOTENCY_CONFLICT` | 保存成功后仅一篇文章或一次更正 |
| 设备文章和类型文章重叠 | 按文章ID去重，分页总数与过滤后结果一致 | 按设备、类型、关键词查看结果一致，类型标签来自档案 |
| 打开已有手册或无图片文章 | 手册由F04读取，无图片按正常详情返回 | 正常阅读正文，保存案例前后同一手册ID复用 |
| 同一工单验收通过后整理案例 | R02/R03读取已验收记录，K03保存后K01可检索，K02保留来源ID | 点击来源返回原维修详情，维修状态与记录保持真实 |

错误响应的 `data.fieldErrors`、`data.conflicts`、`data.missingItems` 按通用约定仅返回适用项。列表和详情分别呈现加载、空数据、失败和重试状态。
