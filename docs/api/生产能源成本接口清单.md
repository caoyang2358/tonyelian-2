# 生产、能源与成本接口清单

状态：设计草案，本文列出的业务接口全部待开发。当前初始化已有的健康检查、工程概览、设备只读接口不在本清单内，也不代表本清单已经实现。

依据：[需求基线](../需求基线.md)第 8—11 节及其中 11.12 排除项、[数据库逻辑表设计](../数据库逻辑表设计与成员使用指南.md)。历史原型的 `production.js`、`domain.js` 只用于核对操作入口和联动，不能把会话内计算、旧两阶段预留或限制性演示逻辑直接当作正式接口约定。

本文覆盖“生产记录”“生产与能源统计”两个入口。订单、库存查询及管理、计划创建、取消、减量、合同金额确认、公共成品正式分配和交付的权威命令在[订单库存排产接口清单](订单库存排产接口清单.md)中定义，本文只引用它们，不新增第二套扣库或状态命令。

## 1. 范围与统一约定

- 全部路径以 `/api/v1` 开头。统一响应信封、分页和错误规则见[接口通用约定](接口通用约定.md)；本文的枚举为研发命名草案，其业务含义按需求基线执行。
- 二期新记录 ID、业务请求 `requestId` 用字符串。共享车间、表计、设备、参数 ID 保留已有身份，不把某次种子 ID 写死为车间一或车间二。
- 吨数使用 decimal 字符串，例如 `"6.300"`；金额总额人民币元使用 `"600000.00"`。均价、能源单价、比例用保留必要精度的 decimal 字符串，中间不先截到分。金额尾差由统一固定规则平衡。
- 业务日为 `YYYY-MM-DD`；实际起止和服务器记录时间使用带时区时间。统计归属为 `Asia/Shanghai` 的实际生产/用能日，不使用补录日或计划日替代。
- 副作用写命令包含 `requestId`、`operatorName`；修改、更正、删除或推进已有对象时，`expectedVersion` 与响应 `version` 均为非负 JSON 整数，不是 ID 字符串或不透明字符串。创建新独立对象不传其尚不存在的版本。
- 新增实际子记录涉及已有任务、订单或归集范围时，校验其适用的父对象版本；多对象条件放入 `expectedVersions`，其中每个 `version` 仍为非负 JSON 整数。更正校验原记录版本，不用页面本地计数替代服务端版本。重复请求返回同一次成功结果，不能重复投料、入库、出库、预留或计费。
- 重要更正、补录、超差放行和不足量结束填写 `reason`。普通新增可携说明，涉及缺项的真实事实可以保存，不能要求先填一个虚构金额。
- 未知值用 `null`，完整性用 `missingItems` 描述，不能用 `0` 冒充。已确认合格量为零、实际耗能为零或有效单价确认为零，是可以成立的已知值。
- 查询列表支持筛选、分页和稳定排序。任务查询区分计划日期、实际日期；实际记录查询按真实业务日筛选，不能将列表分页结果当作全日或全订单统计总量。统计接口返回全筛选范围的独立汇总。
- 查询不会修改余额，也不新建已生效核算批次或刷新持久化成本结果。生产事实的实际保存命令在二期后端同一事务内调用统一库存服务；前端不得再补一次“扣库存”请求。
- 库存数量、预留及库存成本账由共用库存服务统一提交；生产和核算模块提供真实来源及计算份额，不能各自写另一套余额。核算补差也通过同一成本账入口，不另造数量流水。
- `version`、库存流水 ID、归属 ID、核算版本 ID、重要修改记录 ID 随响应提供，便于后续操作和追溯。

### 2.1 一次投料、多个产出与共享需求

1. 投料保存实际铜板吨数和材料总金额，后续称重引用同一投入/归集依据。两次称重不能再次累计同一材料金额或再扣一次铜板。
2. Φ8 铜杆产出先进入总库存。计划任务可覆盖多个订单，实际产量只增加一次；铜杆订单需求份额不是客户铜丝完工量。
3. 正常同日归集应能说明多笔投入与多次称重的关联，研发统一归集键，不要求用户选择复杂成本时点。
4. 正式接口不把原型的演示预填量当作真实称重，也不从合格铜杆吨数倒算实际铜板投入。`manualPlannedRodTon` 及 `productionScope/productionScopeVersion` 是排程依据，不是实际投料或领用量；实际事实改变剩余加工范围时返回范围变更及待重核提示，不因此阻止合法事实保存，也不按计划或数量比例回写实测值。
5. 保存数量与库存变化同事务；缺材料金额、能源或价格时，保留 `null` 与来源缺项，库存数量仍按真实事实变化。

### 2.2 领杆与接收补录的单次扣库约束

- `sentQuantityTon` 为实际交出吨数，必须大于零；`receivedQuantityTon` 为实际接收吨数。实际接收尚未补齐时可为 `null`，不能默认为 `sentQuantityTon` 或 `"0.000"`。
- 交出已经真实发生并保存时，该交接记录关联一次出库。接收缺失则 `handoverState=PENDING_RECEIPT`、`errorRate=null`，不能显示正常交接完成或据此假定已具备现场加工条件。
- 后续补接收走 S2-R11，携同一个 `handoverId` 和原版本。仅补接收不产生新的出库或成本扣减；实际交出重量更正只处理新旧差额。
- 两个重量已知时，误差率为 `abs(receivedQuantityTon-sentQuantityTon)/sentQuantityTon`。小于等于 5% 正常；大于 5% 原因和人工放行依据必须保存，不能通过改重量强行过检。
- `errorRate` 使用比例 decimal 字符串，例如 `"0.050000"` 表示 5%；前端可格式化为百分比，不能与比例值混用后再次判定放行。
- 明确全部供某订单的领用，其上游成本为交出吨数乘该次适用铜杆均价。差额成本已含其中，不另建损耗费用、废品或不合格量。
- 一次业务涉及多项接收任务时，按已知任务明细记录和汇总；明细不齐为待补充，不按未知比例自动平摊，也不把全部总出库各记给每个订单。

### 2.3 同次同规格铜丝称重与公共差额

S2-R12 的关键请求数据：

| 字段 | 含义 |
| --- | --- |
| `productionGroupId` | 同次实际归集键；已有组继续引用，新组由后端生成，不等同来源铜杆批次 |
| `taskIds` / 任务关联明细 | 实际对应的车间二任务；单任务为一个，同规格多个顺序任务可关联同一次合并称重，不改变一条产线同刻一项任务的约束 |
| `materialId` / `specification` | 一个确定的合格铜丝物料规格，后端核对任务与订单，不能一行混多个规格 |
| `actualDate`、实际起止/执行记录 | 真实生产归属，不强制等于计划日 |
| `qualifiedQuantityTon` | 本次新增合格铜丝总量，按 0.001 吨记录，不是当日已经登记过的累计量 |
| `allocations` | 各订单及关联任务的实际归属依据；后端核对订单规格、剩余需求和当前版本，按已确认规则形成最终归属 |

响应返回最终 `allocations`、每项数量/归属 ID/预留 ID、`publicQuantityTon`、库存流水和完整性。公共量通常为总量减各归属量，**不要求再称一遍公共铜丝**。

- 归属总量不能超过本次合格总量；不能占用订单不再需要的份额，超产保留为公共库存。并发导致订单需求变化时给出冲突或明确的最终分配差异，不能改写原始实测总量。
- 同一次实际总产量只记录、统计及入库一次，不能按 `taskIds` 或订单数复制总产量。多任务关联需要明细时由数据设计落实。
- 同次同规格产出总成本按合格数量分给订单与公共份额；例如 10 吨成本 60 万、A 8 吨，则 A 48 万，公共 2 吨 12 万。
- 直接生产归属和后续公共库存分配是不同来源。S2-R12 已形成的有效直接归属预留不能再从公共分配接口预留一次。

### 2.4 实际结束、订单不足及更正

- S2-R05/S2-R15 保存实际开始/停止/当天结束，是登记信息，不是遥控设备。
- 只登记停止但尚未称重时，产量仍待统计；不能自动填零或宣称已足量完成。补录后按真实日更新汇总，不重写原计划来隐藏差额。
- S2-R16 的不足量结束保留原要求、实际量、差额和原因，已有合格成品仍可用于本单后续交付；不自动归公共，也不将部分实际交付标成足额履约。
- 正常结束结论依据已保存实际/已确认成品分配。资料未齐可以保存停止事实并返回待统计项，不能以状态标签代替尚缺的真实数据。
- 合同/实际约定金额由订单模块的唯一金额确认命令维护，S2-R16 不另设一套金额来源。金额未确认或成本未齐，核算中；不足结束在确认实际约定金额且成本齐全后才估算盈亏。
- 更正保存原/新值、原因、人员、时间及来源。仅补材料金额、改说明或补接收不能重复增加/扣减实物；实际重量发生变化才处理对应数量差额。
- 已结束或已取消不意味着删除真实事实或禁止合理补录。应区分“补记已经发生但尚未登记的停止/投入/产出”与“又安排新的生产”；前者沿原任务及版本保留依据、更新关联库存和成本，后者不能绕过计划和订单状态校验。
- 已有下游记录不是删除历史的理由，也不能无条件绕过校验。若当前更正会导致负库存、侵占其他预留或与已交付事实冲突，返回关联 ID 与冲突信息；先核实相关真实记录，不能用假退料/假收货平账。

### 3.1 用能日期与缺失处理

- 按实际用能日取当时有效价格，不用订单录入日、补录日或查询当天价替代。正常新增 11 月价格不改变原有 10 月核算；对原错误价格的更正另留痕补算。
- 可维护通用或指定车间价格。研发在统一价格服务中明确范围匹配及版本规则，并在结果中返回匹配范围和价格来源，调用方不能各取一套价格。
- 有合格产出日，车间二订单权重为当日实际归属合格量除以当日全部实际合格量，公共部分也进入分母。例如 A3/B4/公共3，共 1000 kWh，分别为 300/400/300。
- 明确无合格产出、尚未称重、部分记录未齐是不同状态。尚未称重或分母未完整时先待核算，不能把“没有查询到称重行”直接当成确认零。
- 缺单价时单价与费用为 null；缺表计时消耗及费用为 null，不拿零或其他范围总表代替。已有计量且确为零则保留已知零，与缺测分开。
- 当前开发快照没有车间二独立煤气总表；API应返回缺计量，不因定义了煤气价格或创建了数据库行就声称已有实际计量能力。
- 来源采纳/补齐依赖既有采集或来源资料更新及可追溯读取，二期核算保存消耗、质量、刷新时间、价格、规则等快照，不能只保存可被一期刷新覆盖的源表主键。

### 4.1 两种均价与费用不重复

**铜杆：**入库成本＝该次实际铜板材料总金额＋应归入的车间一能源费用。新铜杆与原库存合并后的均价＝对应总成本÷全部铜杆实物吨数；含在库已预留实物。订单实际领用按交出量带入上游成本，不再加一次铜板或车间一能源。

**公共成品：**同次同规格合格产出，按实际数量把对应铜杆及车间二能源成本拆给订单与公共部分。仅仍未分配的同规格公共数量和成本参与公共均价，后来公共入库不重算原订单已明确归属的生产份额。公共库存正式分给新订单时只关联一次成本、退出自由公共池；交付前仍在总实物和总在库价值中。

期初铜杆数量及总成本由库存模块统一登记，缺成本为待补充；成品初始默认零，不能用假设的初始成品成本演示“已完成”。实际取消/减量归公共、成品分配与交付的成本流转跟随其权威业务命令，不由 K05 重做数量操作。

### 4.2 核算完整性与利润字段

建议查询结果至少包含以下语义，最终字段由统一接口契约锁定：

| 字段 | 语义 |
| --- | --- |
| `accountingState` | 核算中、资料齐全或不展示利润等结果，不能只返回一个数字；与订单查询使用同一语义 |
| `knownCostAmountYuan` | 已有充分依据部分的金额；完全没有可核算项时为 null，有已确认零成本项才可为 `"0.00"` |
| `totalCostAmountYuan` | 全部必要成本已齐时的总额；缺材料、期初、能源、价格或必要归属时为 null |
| `estimatedProfitYuan` | 满足该订单对应结束和金额、成本条件才有值；其他情况为 null |
| `profitDisplayable` | 是否允许展示最终估算盈亏，取消始终 false |
| `missingItems` | 缺项列表，可含来源类型/ID、实际日、字段及说明；不另造“未知成本”业务模块 |
| `costRunId` / `version` | 当前核算依据版本及更正/补算关联 |

- 正常需要新生产的订单，在实际生产结束、金额确认且必要成本齐全后估算盈亏。
- 成品库存直接满足的订单，确认成品归属、金额和成本齐全后按“无需生产”路径核算，不补造生产完工事实。
- 不足量结束保留原需求/实际/差额；按人工确认的实际约定金额和齐全成本估算，不能自动按原合同全额或产量比例推金额。
- 减量后金额由订单模块按新约定人工确认，允许金额不变；未明确前不出最终利润。
- 取消订单只展示历史实际、成本及转公共依据，不显示利润，不默认取消收入为零，也不把全部成本清零或全部认定损失。
- 单价正常更新不回写原已核定结果；原始错误或缺项更正补齐可以留痕补算。调用补算不能将后来正常的新采购价/能源价追套到此前事实。
- 本版没有完整财务、税费、人工、运费、折旧或退款计算模块，结果明确标为材料与能源简化估算。

### 4.3 自动触发与受控补算

S2-R08/R11/R13、S2-E06 等命令保存真实更正后，由后端识别受影响库存和订单并触发核算。可以同请求完成，或返回 `costRunId` 待查询；不能先显示“最终已核算”却没有完成的成本结果。

K05 用于明确补齐来源后补算或失败重试，不新增每次生产后必须再点一次的业务审批。读查询不静默改原始事实；异步补算采用同一来源版本和幂等规则，新结果与旧版本可核对，失败不覆盖上一个有效核算。

## 6. 失败与异常结果必须可区分

以下为必须表达的业务含义；统一 HTTP 状态及错误码命名由总约定维护。

| 情况 | 应返回什么，不能做什么 |
| --- | --- |
| 原记录/任务/订单版本变化 | 冲突及当前版本/影响来源；回到原记录或草稿核对，不加一轮人工审批 |
| 实际领用量超过自身有效预留＋公共可用 | 库存冲突；不得侵占其他订单预留、超卖或把未来供料当现货 |
| 交接大于 5% 且无原因 | 校验失败、缺少超差原因；不自动报修、不改称重数据 |
| 接收待补 | 同一交接有效版本、接收 null、误差待判断；不能默认正常，也不能补接收再扣一次库 |

| 更正影响已交付或已转归属事实 | 明确关联及可核对冲突；不能静默删掉下游记录或任意平账 |
| 取消/不足/减量 | 分别按相应规则；不能通用一个“关闭”导致成品、金额、成本全部回退 |
| 数据库或核算暂不可用 | 安全错误/待重试状态；写事务失败不返回虚假成功，不输出内部 SQL/密码/堆栈 |
