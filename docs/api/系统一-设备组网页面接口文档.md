# 系统一 · 设备组网页面接口文档

日期 2026-11-03。版本 v0.1。N01、N02 已实现，设备和测点共享接口按各自模块进度联调。本文沿用[系统一接口清单](系统一接口清单.md)的路由，细化的 DTO、排序和空布局约定供联调评审。

## 1. 页面操作和接口

| 操作 | 方法与完整路径 | 负责方 |
| --- | --- | --- |
| 读取车间列表并同页展示各车间示意图 | GET `/api/v1/reference-data`（BASE-04） | 设备管理 |
| 打开车间示意图 | GET `/api/v1/network-layouts/{workshopId}`（S1-N01） | 设备组网 |
| 选取可放置的设备和测点 | GET `/api/v1/equipment`（S1-E01）、GET `/api/v1/sensors`（S1-P01） | 设备管理 |
| 点击设备查看信息 | GET `/api/v1/equipment/{equipmentId}`（S1-E02） | 设备管理 |
| 点击测点查看资料、参数和最新值 | GET `/api/v1/sensors/{sensorId}`（S1-P02）、GET `/api/v1/sensors/{sensorId}/parameters`（S1-P06）、GET `/api/v1/sensor-parameters/{parameterId}/latest`（S1-P09） | 设备管理 |
| 保存位置、测点标记和连线 | PUT `/api/v1/network-layouts/{workshopId}`（S1-N02） | 设备组网 |
| 取消编辑 | 恢复上次读取的布局 | 页面本地操作 |

共享接口的字段以[设备管理页面接口文档](系统一-设备管理页面接口文档.md)和[首批接口约定](首批接口约定.md)为准。设备列表升级前只能读取当前基础字段，前端先按车间过滤。新增布局接口和共享接口的 ID 使用字符串，消费旧列表时在前端转换 `id` 和 `workshopId`。

## 2. S1-N01 读取布局

| 输入 | 类型 | 规则 |
| --- | --- | --- |
| `workshopId` | 字符串，路径必填 | 有效车间 ID |
| `includeLatest` | 布尔值，查询参数 | 默认 false，true 时附带布局测点的最新值快照 |

`data` 示例。设备和测点 ID 为联调示例。

```json
{
  "workshopId": "1",
  "version": 3,
  "updatedAt": "2026-11-03T09:15:00+08:00",
  "nodes": [
    {"nodeId": "equipment-7", "kind": "EQUIPMENT", "objectId": "7", "xPercent": "25.5", "yPercent": "40"},
    {"nodeId": "sensor-12", "kind": "SENSOR", "objectId": "12", "xPercent": "30", "yPercent": "35"}
  ],
  "edges": [{"edgeId": "edge-1", "fromNodeId": "equipment-7", "toNodeId": "sensor-12", "label": "监测位置"}],
  "processSteps": ["铜板上料", "熔化", "保温", "结晶水冷", "牵引", "轧制", "冷却清洗", "Φ8 铜杆收卷"]
}
```

- 未保存过的有效车间返回 `version: 0`、`updatedAt: null` 和空节点、空边。GET 无写入。车间不存在返回 404。
- `processSteps` 为只读展示顺序。车间二依次展示铜杆接收、放线、多道次冷拉、在线测径、成品收卷及规格检验。设备形态和名称由页面结合设备档案渲染。
- `includeLatest=true` 时拟返回 `latestBySensorId`，键为测点 ID，值为该测点参数快照数组。每项含 `parameterId` 和 S1-P09 的 `data` 字段，沿用其读数、单位、采集时间、质量和监测状态。参数无读数时保留该参数，读数与采集时间按 P09 返回。测点无参数时返回空数组。布局数据可用而采集快照读取失败时，页面可改用默认查询并单独提示读数读取失败。

## 3. S1-N02 保存布局

提交 JSON 全量替换当前车间示意布局。字段如下。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `requestId` | UUID 字符串 | 必填，超时重试沿用 |
| `operatorName` | 字符串 | 必填，手填操作人 |
| `expectedVersion` | 非负整数 | 必填，来自 N01，0 代表首次保存 |
| `reason` | 字符串或 null | 选填，布局调整原因，最多 1000 字；省略或留空不记录原因 |
| `nodes` | 数组 | 必填，元素结构见 N01；空数组表示清空节点 |
| `edges` | 数组 | 必填，元素结构见 N01；空数组表示清空连线 |

节点 `kind` 取 `EQUIPMENT` 或 `SENSOR`。每个布局内 `nodeId` 唯一，同一设备或测点可在不同位置重复标记，每个标记使用独立的 `nodeId`，并指向同一个 `objectId`。节点和边的自身 ID 是客户端布局键，业务对象仍用 `objectId`。坐标是以画布左上角为原点的百分比，十进制字符串，0 到 100 均可。按 V3 物理表精确保存，最多六位有效小数，超出精度返回 400。设备必须属于所选车间，测点通过实际设备归属核对车间。边的两个端点须为本次提交的不同节点，`edgeId` 在布局内唯一，`label` 可为 null。移走节点时一并提交删除相关边后的完整数组。

请求示例 `PUT /api/v1/network-layouts/1`。

```json
{
  "requestId": "11d1523a-2f42-466d-8253-35f5fc197c72",
  "operatorName": "张工",
  "expectedVersion": 3,
  "reason": "调整测点标记位置",
  "nodes": [
    {"nodeId": "equipment-7", "kind": "EQUIPMENT", "objectId": "7", "xPercent": "25.5", "yPercent": "40"},
    {"nodeId": "sensor-12", "kind": "SENSOR", "objectId": "12", "xPercent": "32", "yPercent": "35"}
  ],
  "edges": [{"edgeId": "edge-1", "fromNodeId": "equipment-7", "toNodeId": "sensor-12", "label": "监测位置"}]
}
```

成功返回 HTTP 200，`data` 使用 N01 的基础布局结构并附 `changeLogId`。服务端在同一事务检查版本、引用并保存布局和变更记录，重复提交按[接口通用约定](接口通用约定.md)返回首次结果。E15 `p2_network_layout` 负责布局持久化。拖动测点与编辑连线只影响示意布局，实际设备归属和工艺顺序由既有业务数据决定。

## 4. 异常处理和交接验收

| 场景 | 接口结果与页面行为 |
| --- | --- |
| 车间不存在 | 404 `NOT_FOUND`，刷新可用车间 |
| 坐标越界、重复节点 ID 或悬空边 | 400 `VALIDATION_ERROR`，定位出错节点或边并保留草稿 |
| 被引用对象已移出车间或被删除 | 409 `STATE_CONFLICT`，返回冲突对象，刷新候选后重新编辑 |
| 他人先保存同一车间布局 | 409 `VERSION_CONFLICT`，保留本地草稿并提示重新读取版本 |
| 同一请求 ID 改了内容 | 409 `IDEMPOTENCY_CONFLICT`，新提交生成新的请求 ID |

1. 两个车间分别加载，首次保存后刷新恢复节点和连线，取消编辑后刷新保留原布局。
2. 点击设备与测点时使用真实 ID 读取共享接口。一个测点含多个参数时分别展示，缺读数时展示采集状态。
3. 用两份相同版本的草稿依次保存，后提交者得到冲突。重复发出第一次成功的请求时，版本与变更记录只增长一次。
4. 模拟无效坐标、悬空边、跨车间引用，保存失败后原布局完整。成功拖动测点后核对设备与测点主数据归属仍与编辑前一致。

设备和测点接口未就绪时，页面可用标明为模拟的共享 DTO 开发。最终联调以真实共享 ID 和二期数据库保存结果验收。组网展示采用二维示意，现场尺寸、工程管网和设备控制均在本页范围之外。

两个车间的示意图在同一页上下展示，各自编辑和保存。常规编辑界面仅选择连线端点。接口保留可空的 `label` 字段用于兼容历史数据，新建连线默认提交 `null`。出现版本冲突时，页面可查看已保存布局，再返回本地草稿核对。
