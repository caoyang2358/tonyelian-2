# 系统一设备管理页面接口文档

日期为 2026-11-04。设备管理 33 条接口（E、S、C、F、T、P）后端已全部实现，前端页面全部接入，实现状态与遗留项见文末。业务范围以需求基线第 12 节为准。[需求基线](../需求基线.md) · [系统一接口清单](系统一接口清单.md) · [首批接口约定](首批接口约定.md)

表内路径统一省略 `/api/v1`。JSON 响应采用 `code, message, data, timestamp`。分页集合返回 `data.items, page, pageSize, total`，默认每页 20、最大 100。新增接口的 ID 为十进制字符串，版本为非负整数，业务日按 Asia/Shanghai，时刻附带偏移。Decimal 传字符串，未知数据传 `null`。文中 W 表示 `requestId` 和手填 `operatorName`，U 表示 W 加 `expectedVersion` 及必要 `reason`。成功重试先查幂等结果再验版本。 [接口通用约定](接口通用约定.md)

| ID | 方法及路径 | 请求 | 返回及验证 |
| --- | --- | --- | --- |

**Sensor** 可写字段为 `sensorCode,name,equipmentId,sensorType,location,purpose,enabled`。详情另含 `sensorId,dataSource,hasHistory,configurationState,version,monitoringStatus`。拟定 `purpose` 为可空字符串，可来自人工确认的测点或技术资料，也可据已确认参数定义展示用途。缺少依据时为 null。组网节点位置保存在布局中，设备归属由本接口读取。

**Parameter** 包含 `parameterId,sensorId,parameterCode,name,dataType,unitCode,decimalPlaces,samplingIntervalSeconds,processId,enabled,rule,ruleVersionId,version`。新增指定编码和数据类型，后续保留采集映射身份。配置更新接收名称、单位、精度、采样周期、工序、启用和规则。单位和工序引用须有效，周期为正整数或 null，精度为非负整数。数据类型沿用 DECIMAL、INTEGER、BOOLEAN、STRING。真实采集通过 `sensorCode+parameterCode` 对应。

**Rule** 拟用 `normalLower,normalUpper,alarmLower,alarmUpper,triggerMode,durationSeconds,enabled`。边界用十进制字符串或 null，校验有值边界的上下关系。普通模式 SUSTAINED 在配置有效时使用正整数持续秒数。关键模式 IMMEDIATE 的持续秒数为空。缺配置显示待配置。修改判断依据时，同一事务保留旧规则，相关活动事件以 `RULE_CHANGED` 结束，下一条有效数据按新规则判断，维修单维持独立状态。 [系统一接口清单的 R16 约束](系统一接口清单.md)

**Latest** DTO 供设备测点页和组网页共用。来源为一期最新值，历史查询来源为原始采集记录。数据来源区分模拟和现场，状态依据由采集配置及质量判断。

| 字段 | 拟定类型及含义 |
| --- | --- |
| `parameterId,sensorCode,parameterCode` | 参数 ID 字符串及采集映射编码。 |
| `value,valueText` | 十进制字符串或 null，文本值或 null。按实际来源表达。 |
| `unitCode,qualityStatus,limitStatus` | 来源单位、质量及限值状态，可空。限值状态与持续异常事件分开。 |
| `collectTime,refreshTime` | 带偏移的采集及刷新时刻，可空。 |
| `monitoringStatus` | 拟定 ONLINE、STALE、OFFLINE、UNKNOWN、DISABLED。缺读数时为 UNKNOWN，停用为 DISABLED，离线须有判定依据。 |
| `dataSource` | 来源标识，可空。模拟来源在页面明确标识。 |

## 异常与联调验收

| 场景 | 预期处理 |
| --- | --- |
| 当前只读联调 | 直接调用 E01，验证七个字段、数字 ID 及现有列表。后续筛选和分页以服务端实现为验收条件。 |
| 旧设备未补档 | E02 正常显示共享资料，未知字段待补，版本 0。只打开表单无业务写入。 |
| 新增及更正档案 | 重试同一 requestId 只产生一次结果。刷新和重启后仍可读回。两个客户端用同版本编辑时后提交者收到 409，页面重新读取。 |
| 参数无效或对象不存在 | 400 显示字段提示，404 提示对象不可用。重复编码、版本不符、相同幂等键内容变化或有引用删除返回相应 409。数据库不可用按 503 显示失败状态。 |
| 误建删除 | 关联检查未知时禁用。无关联且二次确认后才提交。并发建立关联时服务器拒绝。删除后历史仍可查，原请求重试返回首次结果。 |
| 合同关联及文件替换 | 一份合同覆盖两台设备，两端显示同一合同及附件。替换后的文件更新时间及内容更新，知识页引用原附件 ID。 |
| 期限待补 | 日期缺失时剩余天数为 null。分别调整质保和维保提前量后查询结果更新。 |
| 多参数与缺读数 | 新测点配置后可查参数映射。没有实际采集时 P09 返回缺值，组网显示用途和来源空态。读取和配置流程不改原始采集库。 |
| 规则变更 | 同一异常持续时只保留一个事件。改变规则时旧证据可查，受影响事件按规则变更结束。已有维修单状态保留。 |

设备档案先用首批契约联调。附件、供应商、合同、期限和测点的响应示例可作为后续开发联调依据，状态以实际后端为准。运维记录通过巡检、异常、维修查询按设备过滤。 [系统一接口清单](系统一接口清单.md)

## 实现状态与遗留项（2026-11-04）

33 条接口（E01—E06、S01—S04、C01—C04、F01—F05、T01—T03、P01—P11）后端全部实现，前端全部接入，数据库除 V8 的提醒设置初始行外无结构变更。

页面归属：

| 接口 | 落在哪个页面 |
| --- | --- |
| E01—E06 | 设备管理列表页；E02—E06 在设备详情抽屉的「档案信息」「变更记录」两个页签 |
| S01—S04 | 设备详情抽屉「供应商」页签 |
| C01—C04 | 设备详情抽屉「维保合同」页签 |
| F01—F05 | 设备详情抽屉「附件」页签 |
| T01 | 设备管理列表页头部的「期限提醒」抽屉 |
| T02/T03 | 同一抽屉内的「提醒设置」行内展开区 |
| P01—P11 | 设备详情抽屉「测点」页签（展开测点看参数、读数与规则版本） |

读数显示口径：后端按契约原样返回 `DECIMAL(20,6)` 字符串（P09 `value`、P10 `value`），精度是采集侧的真实精度，接口不改；页面统一按参数 `decimalPlaces` 补齐小数位（`frontend/src/lib/reading.ts`），因此参数行与历史读数列表对同一个值给出同一种写法。补齐不走 `Number` 转换，避免 20 位数值在末位丢精度；文本型读数（如「开」）原样显示。

事件结束的实现口径：判断依据变化并追加规则快照后，在同一事务里把该参数仍挂着的活动事件置为结束——`end_reason='RULE_CHANGED'`、`recovered_at` 保持为空（规则变更不是恢复）、`version` 加一（A03 的人工处理按这个版本做乐观锁）。唯一索引 `uk_p2_alert_active_parameter` 限定同一参数至多一条活动事件，所以「受影响事件」只会是 0 或 1 条。结束动作由 `AlertEventTerminator` 承载，当前实现（`JdbcAlertEventTerminator`）直接写表；事件服务的读取与人工处理（S1-A01—A04）尚未开发，等它提供接口后只替换实现，P08 主流程不动。
