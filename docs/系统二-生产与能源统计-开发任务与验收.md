# 系统二 · 生产与能源统计开发任务与验收

本文件用于拆分前后端任务并复现联调结果。业务依据为[需求基线第 10、11、17 节](需求基线.md)，接口沿用[生产、能源与成本接口清单](api/生产能源成本接口清单.md)的 S2-E01–E06、S2-K01–K06。原始事实、计划和库存分别由[生产记录开发指南](系统二-生产记录-开发指南.md)与[订单与计划开发指南](系统二-订单与计划-开发指南.md)提供。

## 1. 任务依赖和交付

| 任务 | 前端交付 | 后端交付及接口 | 进入条件与签收内容 |
| --- | --- | --- | --- |
| 1. 车间总量和来源读取 | 默认显示今日两个车间的实时结果，提供车间、日期筛选和电、水、煤气、合格产量四项结果。点击数值可展开来源、完整性和缺项。显示读数或业务资料的模拟来源标记 | S2-E01/E02，读取一期能源表的适用车间计量及质量，以二期实际称重计算产量。统一日与小时范围选择、计量范围和来源质量 | 参考数据、实际记录查询及只读能源来源适配可用。先验收两个车间分别汇总、缺项和同源去重。今日尚未录全时展示已知数量及待核算 |
| 2. 单价维护和匹配 | 价格列表、能源及范围筛选、新增生效价格、历史错误更正。填写单位、生效日、原因，展示适用范围和历史版本 | S2-E04/E05/E06，统一通用与车间价格匹配，唯一性、版本、幂等和更正留痕。更正后返回补算进度或结果 | 任务 1 的单位和来源已统一。新增价格与错误更正分别验收，核算服务接入前保留待核算来源 |
| 3. 车间二每日分摊 | 日结果展示合格量分母、订单和公共数量、比例、能源份额、价格与金额。无产出和待称重显示对应依据 | S2-E03，按完整实际合格量进行日总耗分摊，公共部分保留份额。保存分摊规则与来源快照供核算追溯 | 生产归属、R14 零产出、R18/R19 当日录全确认及任务 1–2 可用。先验证录全条件，再测试 A3/B4/公共3 的完整分母 |
| 4. 铜杆和公共成品成本 | 库存成本查询分列实物、预留、自由公共份额、已归属份额、总在库价值与缺项，展开来源流水 | S2-K01/K02，复用统一库存服务。铜杆按全部实物均价，公共成品按同规格自由份额均价。初始成本、实际材料及车间一能源形成可追溯来源 | 订单与计划的期初、生产实际、归属和库存流水可用。先验收加权均价，再验收分配、释放和交付 |
| 5. 订单核算和盈亏 | 订单列表与详情显示合同/约定金额、已知成本、完整成本、核算状态及估算盈亏。可沿明细查原材料、能源和库存来源 | S2-K03/K04，统一订单结果与金额版本，追溯铜杆领用或公共成品带入成本、车间二能源，分别处理正常、取消、减量、不足量和无需生产 | 任务 3–4 及订单结束、金额、交付结果可查。成本或金额缺失时返回缺项，齐全时核对简化估算 |
| 6. 补算和版本发布 | 原始资料补齐或更正后显示后台处理状态、当前有效结果、新旧版本和失败重试。查询结果显示来源变更提示 | S2-K05/K06，按来源确定受影响范围，输入快照、幂等、并发版本校验、候选结果与完整发布保持一致。失败保留上个有效结果及失败依据 | 任务 3–5 的来源关系和算法可复现。通过补齐、历史更正、冲突和故障测试后签收 |

任务 1 和任务 2 可以并行开发，任务 3 使用相同来源及价格服务。任务 4 先保留成本输入和变动引用，与订单、生产的数量链路并行联调。任务 5 汇总统一成本结果。任务 6 的来源版本及发布设计在核算持久化开发前确定。

当天记录由生产页使用 S2-R18 查询状态，通过 S2-R19 以车间、实际日及当前版本明确确认「当日录全」。补录或更正使受影响日期的确认失效，跨日更正涉及原日和新日。统计据此识别完整分母。日期已过去、已有正称重行或某项 R15 任务结束都只能作为已知事实。未录全时展示已知数量、核算状态和缺项，盈亏为空。车间一同次同日生产材料总成本按各次实际合格铜杆重量分配，当天能源按全天实际合格铜杆重量分配，投入引用按原始投料 ID 去重。

## 2. 开发数据与第一轮验收

所有验收先使用独立二期开发 MySQL。每组场景从独立夹具或受控快照开始。能源数据由只读适配器夹具或隔离开发库提供，真实采集库按现场验证流程读取。车间、物料、订单和记录使用实际返回 ID。以 D 作为已发生的业务日，来源、价格、订单和数量均标为联调数据，经办人填「联调」。

## 6. 补算、失败和结构升级

| 复现方法 | 应验结果 |
| --- | --- |
| K05 根据已经补齐的期初成本、材料金额、能源价或原始更正触发补算，K06 查过程 | 返回真实 `costRunId`、来源版本和影响范围，能够查询过程、缺项及新旧结果。自动触发和手动失败重试沿用同一规则 |
| 同一 K05 请求超时后重试，再并发提交相同 `requestId` 和内容 | 一个补算业务结果生效，重放同一结果 ID，库存、原始生产与称重均可逐笔核对。相同请求 ID 改内容返回幂等冲突 |
| 补算运行时，另一会话更正其所依赖价格或称重版本 | 发布时核对来源修订号和已发布版本。旧输入版本的候选不能覆盖最新有效输入对应结果。返回可定位的冲突/重试状态，前端保留原始有效结果并标明来源已变化，后端按最新来源版本重新处理 |
| 已有成功版本，补算发现当前来源存在必需缺项 | `INCOMPLETE` 批次可原子发布新的已知部分和缺项快照，受影响完整金额及盈亏为空。历史成功版本仍可查，当前查询按新发布版本反映缺项。补齐资料后以同一来源链形成后继结果 |
| 已有有效版本，补算发生数据库或计算故障，或候选尚未提交 | `FAILED` 或未提交的候选不推进当前发布指针。K01–K04 仍选上一有效版本并说明来源变化及处理状态。故障排除后可重试，数量事实继续按已成功原始事实可查 |
| 在候选能源分摊、库存成本和订单成本已写入部分时注入故障 | K01–K04 仍读同一个上一有效结果集合，候选版本状态能解释失败。成功发布时相关份额、订单和库存来源具有同一发布依据 |
| 先以旧 V6 结构和已有价格、核算批次、成本流水建立快照，再执行未来增量迁移 | 价格和核算历史 ID、来源关系、金额及缺项可回查。旧版本的输入不全时标明缺项，完整发布信息按迁移规则恢复。空库迁移后以相同夹具复验 |

受影响范围按来源关系包括必要的后继库存与订单结果，重算范围及未受影响结果在同一发布版本下可核对。核算批次和候选状态可查，全历史回放可作为实现选择，验收以发布一致性、来源可追溯和上述数值结果为准。

## 7. 签收证据和现场核验

开发验收保留提交版本、迁移版本、夹具说明、接口请求 ID、原始业务记录、R19 录全依据与核算版本 ID、事前事后数量和金额、页面与下钻结果。先签收 E01/E02 的实际总量和缺项，再签收 R18/R19 状态及 E03–E06 的日期价格与分摊，最后签收 K01–K06 的库存成本、订单盈亏和补算。字段精度、规则版本、来源快照及发布版本由前后端使用同一契约。

现场另核对车间总表身份、能源类型及单位、实际覆盖范围、日/小时数据生成逻辑与刷新质量、源数据模拟标识、各车间真实单价和生效依据、期初库存总成本、投料材料凭据、交接和称重以及订单金额。实际日计量与生产记录应能同日核对。缺少车间独立煤气表或必要成本凭据时，现场签收记录对应缺项和后续补齐责任。来源与交付处理参照[数据来源说明](数据来源说明.md)及[门户交付与数据责任清单](门户交付与数据责任清单.md)。
