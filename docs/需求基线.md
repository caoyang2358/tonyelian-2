## 3. 统一概念与数量口径

| 概念 | 业务含义 |
| --- | --- |
| 重量 | 铜板、铜杆、铜丝统一以吨记录，保留 3 位小数，即精确到 1 公斤；计划备料的取整见 3.1 |
| 实物库存/总库存 | 已经实际登记入库、尚未实际领用或交付的数量 |
| 预留库存 | 实物中已承诺给订单或任务、其他需求不可再占用的数量 |
| 可用库存 | 实物库存减已预留数量；不能重复分配已承诺的库存 |
| 预期供料 | 尚未实际产出入库、但已列入供料安排的数量；不属于实物库存 |
| 可行性评估 | 正式排产前检查库存、产能、交期和两车间供料能否共同满足订单 |
| 日计划 | 按日期、车间和任务安排的计划产量及所需物料；日期为最小排产单位 |
| 实际产量 | 完工或每日停止后称重登记的合格产出，不能用计划数或工时估计数替代 |
| 订单生产完成数量 | 实际产出中明确归属该订单的最终合格铜丝数量；车间一铜杆归属不计作铜丝完工，既有成品分配不是本次新生产 |
| 可交付条件 | 订单有足够符合规格、可用于交付的成品；不同于已经实际交付 |
| 估算利润 | 简化成本口径下的订单经营结果，不等同于完整财务净利润 |

订单要求量、计划铜杆量、实际铜板投入、实际铜杆产量、实际铜丝产量、库存分配量和实际交付量分别保存，不相互冒充或重复累计。

### 3.1 R17 已确认：重量、金额及计划备料取整

| 数据 | 已确认口径 |
| --- | --- |
| 重量 | 以吨记录，保留 3 位小数，最小记录单位为 0.001 吨，即 1 公斤 |
| 金额总额 | 以人民币元记录，保留 2 位小数，即精确到分 |
| 系统计算的计划铜板量 | 净新增 Φ8 铜杆计划吨数乘 1.05 后，向上取整到 0.001 吨，避免小于计算需求 |
| 实际称重 | 按实测重量记录，不采用计划备料的向上取整，也不按计划值或系数倒算实际产量 |

例如需新增铜杆 1.001 吨，计算铜板需求为 1.05105 吨，系统的计划铜板量取 1.052 吨。10 吨铜杆对应 10.500 吨铜板，已有整公斤结果不再额外加一公斤。

同一确认用料需求先合并后计算、取整一次；后续按日拆分或多订单关联不能再次叠加 1.05 或重复取整增加同一份总需求。实际输入超出约定记录精度时应提示核对，不能静默按备料规则上调实测数。

**基于上述精度的研发约束：**均价、能源单价和分摊比例保留足够的计算精度，不先截成两位再计算；最终金额按分统一舍入，分位尾差按固定规则平衡，保证订单、公共部分和库存余额与来源总成本合计一致。能源表计及传感器原始读数保留已有采集精度、按测点配置展示，不被重量三位小数规则覆盖。

## 4. 订单信息与生产组织

### 4.1 订单基本要求

- 一张客户订单只有一种最终铜丝规格，至少记录需求数量和交付日期。
- R11 已确认：第一版人工录入每张订单的合同总金额，单位为人民币元，作为正常完成订单估算盈亏的金额依据；不要求先建立合同金额自动导入或合同单价推算流程。缺金额时提示待补充，不用零代替。
- 计划铜杆量仍需要另外填写，不恢复“不填写计划铜杆量”的旧规则；铜板计划需求按本轮 R02 确认的固定系数 1.05 计算，不另增成材率参数配置。
- 铜板计划需求量 = 车间一需要新增生产的 Φ8 铜杆计划吨数 × 1.05，详见 5.6。不能直接用铜丝订单吨数作计算基数，也不按 1∶1 换算。

### 4.2 排序及多订单

- 默认按交付日期从早到晚排序并考虑生产；交期相同按录入先后。
- 允许人工调整生产优先级，明确保留调整结果，不能以调整优先级代替修改交期。
- 多个订单可以同时进入计划，不要求前一订单整单结束后才能安排下一订单。
- 每个车间只有一条产线，同一时刻执行一项生产任务；车间一的一项合并生产任务可以同时服务多个订单的 Φ8 铜杆需求，不要求逐单分开生产。车间二按任务顺序加工订单所需规格，当天有剩余产能时可以继续其他订单任务。
- 两车间可以分别服务不同订单，不要求全厂同一时间只服务一个订单。
- 车间一固定生产 Φ8 铜杆，车间二将铜杆加工成订单要求的铜丝规格。

## 5. 库存与物料衔接

### 5.1 三类物料

| 物料 | 当前要求 | 与旧稿的关系 |

| 铜板原材料 | 人工维护期初、实际入库、领用及更正记录；纳入可行性评估，管理实物、预留和可用量；实际投料时人工填写本次材料总金额 | R01、R02 及 R12 材料金额来源已确认，见 5.5—5.6、11.7；不另要求铜板库存均价账 |

| 合格铜丝成品 | 按最终铜丝规格管理实物、预留、可用、分配及交付；第一版初始默认没有成品铜丝库存 | 保留后续生产入库、同规格匹配及防止重复分配，初始默认零不等于今后不管理成品库存 |

原材料库存进入评估，不等于建设完整采购、采购审批、供应商结算或财务仓储系统。库存不足时可以提出采购原材料的建议，但本次未确认采购业务流程。

原有“为订单领取、准备的铜板重量会全部投入生产”继续保留。铜板按实际领用扣减实物及对应预留；实际材料成本取自本次实际投料人工登记的材料总金额，与车间一能源成本归入合格铜杆库存，随铜杆均价带入订单。不增加铜板库存独立均价计算，也不新增废品或不合格量记录来填补差额。

### 5.2 库存分配及预留

1. 查询、评估、试排和方案草稿都不预留库存、不占正式产能；不用先建立临时库存占用才能查看日计划。
2. 系统建议和人工编排汇入同一方案草稿，只有一次人工确认保存。保存时校验当前库存、产能及供料，并在同一后端事务保存计划和对应预留。
3. 成品直接满足订单时不生成生产任务，确认方案后只建立相应成品分配/预留。
4. 分配10吨实物中的6吨后，实物仍10吨、预留6吨、可用4吨；预留不扣实物。
5. 同一确认需求可关联多订单/任务，但后续关联不能重复预留。实际领用或交付才扣实物和对应预留一次。
6. 草稿关闭或放弃不新增、撤销原有效计划或预留；保存成功后关闭不撤销结果。修改或取消已生效安排时按业务规则调整相关预留，原始实际保留。
7. 保存时防止多用户超额承诺；评估通过不表示库存永远不变。失败不得留下半套计划/预留，重复请求不得重复写入。
8. 未入库的计划产出只是预期供料，不属于现货；不能重复承诺给多个需求。

### 5.3 两车间通过库存衔接

车间一合格铜杆 → 实际称重 → 登记铜杆入库 → 车间二依据计划从铜杆总库存领用 → 交接登记 → 拉丝加工。

- 不采用两车间直接、即时绑定的生产模式，不要求车间一一完成车间二立即加工。
- 车间一可以合并生产通用 Φ8 铜杆，日内可以分批完工、称重入库。
- 同一次铜杆生产可以覆盖多个订单，例如一项 7 吨生产安排同时覆盖订单 A 的 3 吨和订单 B 的 4 吨需求；实际合格产出按称重入总库存一次，各订单关联或分配不增加车间总产量。
- 车间二从总库存分配，不要求人工选取车间一的某个来源批次。
- 允许同日供料，但必须先实际称重入库、再领用加工；“计划日期相同”不意味着当天一开始就有料可用。
- 同日衔接需要表达供料先后，具体日内顺序方式待设计；不因此增加分钟级自动调度要求。
- 尚未到料的车间二任务可以预排，但必须显示“待到料”及供料风险。

### 5.4 交接与误差

- 关联接收任务，记录交出重量、接收重量、时间及经办人，不强制选来源批次。
- 误差率 = `|接收重量－交出重量| ÷ 交出重量 × 100%`。
- 误差不超过 5%（含边界）正常确认；超过 5% 时填写原因后允许人工放行。
- 保留真实重量，不能为了通过校验修改实测数。
- R06 已确认：铜杆总库存按实际交出重量出库，并核销本次使用的对应预留；接收重量单独保留，不再按接收重量重复扣库存。
- 例如实际交出 10 吨、接收 9.8 吨，铜杆总库存扣减 10 吨，保留接收 9.8 吨及交接差异 0.2 吨。不能因出库按 10 吨就将接收记录也改成 10 吨。
- 交接差异按真实重量留痕，不自动生成废品或不合格量记录。R12 已进一步确认：明确归属某订单的一次领用，该订单按交出重量乘适用铜杆均价承担上游成本，差异不再额外加一笔费用，详见 11.9。
- 5% 是交接重量误差规则，不是能源分摊、利润误差或产量评价阈值。
- 铜板计划需求的 1.05 系数与本节交接重量误差的 5% 是两个独立规则，不可混用。

### 5.5 R01 已确认：铜板库存维护及预留归属

本项已在本轮逐项对齐中获用户认可：

| 操作 | 已确认规则 |
| --- | --- |
| 期初库存 | 在系统中人工登记当前实际铜板重量 |
| 后续入库 | 铜板实际到货后，人工登记入库重量，增加实物库存 |
| 预留 | 方案一次确认保存成功后，为本次生产用料需求预留现有可用铜板 |
| 预留归属 | 可关联一个或多个订单，不强制一份铜板只属于一张订单；生成日计划后由车间一任务使用已有预留，不再重复占用 |
| 实际领用 | 按实际领用重量扣减实物和对应预留一次；领取的铜板全部投入生产 |
| 数据更正 | 允许更正，保留修改前后数量、原因、时间和手填经办人 |

例如铜板实物 20 吨，确认预留 8 吨后，实物仍为 20 吨、预留 8 吨、可用 12 吨；实际领用这 8 吨后，实物为 12 吨、对应预留为零、可用仍为 12 吨。

本项不增加采购审批或完整采购流程。铜板计划需求量按 R02 和 R17 计算、取整；材料金额及共用铜杆成本归属按已确认的 11.6—11.10 执行。

### 5.6 R02 已确认：铜板计划需求按铜杆补产量乘 1.05

本轮用户已明确确定：

**计划铜板需求量（吨）= 车间一需要新增生产的 Φ8 铜杆计划量（吨）× 1.05。**

R17 已进一步确认：系统最终计划铜板量按上述计算结果向上取整到 0.001 吨，实际投入和产出不采用这种取整。

| 需要新增生产的 Φ8 铜杆 | 计划铜板需求 |
| --- | --- |
| 10 吨 | 10.5 吨 |
| 6 吨 | 6.3 吨 |
| 0 吨，即现有库存和有效供料已足够 | 不因本次需求新增铜板生产用料需求 |

- 计算基数是尚需新安排生产的铜杆量，已利用的铜杆现货不再折算为新的铜板需求；已有生产安排的用料不因重新评估而重复计算、重复预留。现货和有效供料只在得到净新增量时扣除一次；若人工填写的计划铜杆量本来就是净新增量，不再扣一轮库存。
- 该系数用于生产前可行性评估、铜板准备及方案确认保存后的预留，替代另行人工填写计划铜板量的建议。手填计划铜杆需求的既有规则继续保留。
- 多日、多订单铜杆需求合并生产时，按合并后的新增铜杆计划量计算一次；日计划拆分或重排不能把同一份用料需求重复累加。
- 车间一计划产出 10 吨铜杆时，铜板计划需求为 10.5 吨；检查车间一产能时仍按铜杆计划产出 10 吨，不能把投入量与产出日产能混为一谈。
- 第一版按固定 1.05 系数使用，不新增让使用者另行选择成材率或损耗率的配置流程。
- 实际铜板领取和投入、实际合格铜杆产出仍分别登记，不用计划数代替实际，不根据实际铜杆产量自动倒算铜板投入。
- 1.05 表示相对计划铜杆量多准备 5% 铜板的计划口径，不等于已确认实际损耗率为 5%，也不自动生成废品、不合格量或损耗记录。
- 本项不确定原材料单价、库存计价和订单成本分摊，也不将铜丝成品目标直接按 1.05 换算为铜板。

## 6. 订单可行性评估与主流程

### 6.1 对外业务顺序

**新增或选择客户订单 → 先评估一次 → 成品足够则形成分配草稿；不足则联合试排 → 可安排时展示系统建议，需调整时直接人工编排 → 统一方案草稿 → 一次确认保存 → 计划及对应库存预留生效 → 登记实际、出入库与交付 → 统计及订单核算。**

评估内部允许试排两个车间，提前安排铜杆缺口，试算不形成正式任务或预留。需调整分支不返回业务可行性评估入口；数量、产能、防重复占用和供料先后等必要自动校验在编辑/保存时保留。校验冲突在草稿页处理，不新增人工审批。

### 6.2 评估内容与建议

| 检查内容 | 需要回答的问题 |
| --- | --- |
| 同规格成品 | 当前实际可用成品可满足多少需求，还需新生产多少？ |
| 原材料库存 | 铜板是否足够，是否已被已有订单或任务占用，需求依据是否齐全？ |
| 通用铜杆 | 当前可用铜杆及已安排、尚未被其他需求占用的预期供料，何时能覆盖车间二用料？ |
| 两车间产能 | 扣除已有安排、特殊日期限制后，还有哪些日期和数量可排？ |
| 交付日期 | 生产及供料能否在要求日期前满足？ |
| 数据完整性 | 计划铜杆需求、库存、产能等必要依据是否缺失？ |

建议应说明可利用库存、剩余生产需求、铜杆补产缺口及供料日期、产能缺口和可能延期的原因。原材料不足可以建议采购，交期不足可以建议调整交期或协调订单。

物料检查按尚需新增生产的部分逐级展开：已有成品足够时，不再要求为该订单准备新的铜杆和铜板；已有可用铜杆足够时，不为同一需求重复安排车间一补产及铜板投入。不能因为不需要使用的上游材料资料缺失，就阻止使用足够的现有成品交付。

缺少必要数据时应明确提示依据不足，不能将缺失当作零、无限供应或“已保证可行”。可行性计算的具体算法待设计，但上述约束不能省略。

### 6.3 一次确认保存方案、日计划与预留

- 可安排和需人工调整两路都进入同一草稿；用户可查看、调整日期、数量及供料安排。
- 草稿不产生库存预留或正式产能占用，不保留“确认建议—暂存预留—再次确认”的旧流程。
- 确认保存时自动校验当前数据；成功后任务与对应预留同时生效，失败不留下半套结果。
- 只有库存成品即可满足订单时，保存分配/预留，不补造生产任务。
- 保存前库存或产能变化时说明冲突，用户在草稿内修改，无需再次走业务评估入口；不让用户选择技术回滚算法。
- 未保存退出只放弃本次草稿，原有效安排及预留保留；保存成功后退出不撤销。

### 6.4 铜杆必须在排产阶段提前安排

当车间二某日需要铜杆时，在同一次可行性试算和后续日计划生成中，就要检查其用料日期之前的供料，不能到实际领用当天才首次发现缺口、再安排车间一补产。

例如，提前排计划时发现 10 月 31 日车间二需要 **10 吨铜杆**，当前可分配现货只有 4 吨：

1. 检查已有车间一计划，是否已经有未被其他任务占用、可按时入库的供料。
2. 如果没有，缺口为 6 吨，应根据车间一剩余产能和特殊日期约束，在车间二实际用料之前排出这 6 吨。
3. 假设 10 月 30 日有足够产能，可安排当日生产 6 吨；也可以更早，或在能明确先入库后领用的条件下同日衔接。
4. 确认后，现有 4 吨可以按确认结果预留；未来 6 吨仍是预期供料，实际入库前不能把现货写成 10 吨。
5. 用料前实际少产、延迟或未入库，应提示受影响任务，供人工调整。
6. 车间一在可用时间内排不出缺口时，评估和日计划建议就要显示供料不足或延期，不能生成一份看似完全可执行的正常计划。

此例的 10 吨是已明确的铜杆需求，不表示“10 吨铜丝必然只需 10 吨铜杆”。系统不能向已经过去的日期补排未来生产。

### 6.5 R05 已更新：一次保存与关闭放弃

| 情况 | 结果 |
| --- | --- |
| 评估、系统建议或人工编排草稿 | 不占库存或正式产能；关闭即放弃本次未保存草稿 |
| 修改原有效计划但未保存退出 | 本次修改不生效，原有效任务及预留保留 |
| 一次确认保存成功 | 任务及对应预留同时生效；之后关闭不撤销 |
| 保存时库存、产能或供料冲突 | 留在草稿内处理；失败不新增半套有效数据，不要求重新走评估 |

放弃草稿不取消客户订单、不改变实物及历史实际，也不释放原有效预留。重复提交、并发和保存异常由后端保证一致性；不新增有效预留随意倒计时过期规则。

## 7. 日产能、日计划与调整

### 7.1 产能日历

| 情形 | 规则 |
| --- | --- |
| 普通日期 | R03 已确认：车间一和车间二的最大日产能初始均为 10 吨/天，用户可在页面分别修改；不随铜丝规格自动变化，两车间修改后的数值可以不同 |
| 默认日历 | 周一至周日均可排产，不默认周末停产 |
| 特殊日期 | 各车间可单独设置当天可用产能，不限于停产；可降低或调整产能 |
| 停产日期 | 该车间当日产能为零，不影响另一车间利用库存安排任务 |
| 一天多个任务 | 按该车间当日任务计划量合计检查，不超过当日可用产能 |
| 未达到日产能上限 | 可以继续安排其他订单生产，不限制为一天一个订单 |

R03 已确认第一版使用上述默认值及页面维护方式。车间一的产能按合格 Φ8 铜杆计划产出计，车间二按合格铜丝计划产出计；不是铜板投入量，也不是实际产量必须达到的目标。10 吨/天是初始参数，不表示现场实际产能已经核实。真实工作时长仍未核实，本版以天为最小排产单位，不以缺少工时为由阻止按日产能参数排产，也不按工时估算实际产量。

特殊日期的单独设置优先于该车间普通日产能，停产为零，沿用已有确认。修改产能后，应检查受影响的未执行计划；超出新上限或供料受影响时提示人工调整，不静默超排或改写已确认计划，不能回写已经发生的实际产量。

### 7.2 计划生成逻辑

1. 按交期及人工优先级处理需求，扣除已确认分配的同规格成品，得到尚需生产量。
2. 沿用车间二按交期优先、从交期向前寻找可用产能的安排方式；结合特殊日期、既有安排及已发生实际试排加工日期和数量，不因车间一合并生产就要求车间二全部提前加工。
3. 根据已填写的铜杆计划需求，按各用料日期核算现货与可兑现的预期供料，扣除其他已承诺需求。
4. 提前为车间一补排铜杆缺口，按 7.4 尽量集中合并生产；必要时调整车间二日期，两个车间的安排必须联合检查。
5. 原材料是否足够也纳入判断；按新增 Φ8 铜杆计划产量 × 1.05 计算铜板需求，检查相应生产日期的可用铜板，不重复占用已有用料安排。
6. 输出每个日期、车间、订单或任务的安排、数量及物料需求，并说明未排量和风险。

日计划以天为最小排产单位，同日独立任务仍须依次执行；车间一同一项合并生产任务可同时覆盖多个订单需求，不将这些订单拆成必须依次执行的多项铜杆生产，不强制一批一单。

### 7.3 草稿、一次确认与重排

| 情况 | 规则 |
| --- | --- |
| 评估/建议/人工草稿 | 只试算或编辑，不预留、不占正式产能 |
| 一次确认保存 | 当前库存、产能及供料通过校验后，任务与预留一起生效 |
| 未开始的未来计划 | 可合并重排，展示旧新变化，保存时同步更新相关预留，原有效份额不重复占用 |
| 已有真实投入、领用、称重 | 保留原目标及实际，不覆盖历史来消除差额 |
| 某日未完成 | 原计划和实际差额保留，剩余量另行安排 |
| 未保存退出 | 原有效版本不变，本次草稿丢弃 |

人工重排直接在草稿内完成；编辑和保存中的基本自动校验继续保留，不增加一次业务评估或审批。

### 7.4 R04 补充确认：车间一未来未开始需求合并安排

车间一只生产通用 Φ8 铜杆，应将已知且尚未开始的未来铜杆生产需求合并统筹，允许一起调整原有未开始的安排，不必保留每份需求原先分到哪一天。先满足各用料时点之前的累计供料需求，再在物料和日产能约束内尽量集中、适当前移；不默认按天平均分摊，也不以每张订单或单份需求各自占用多少天作为优化目标。

例如，假设提前为 10 月 25—29 日制定计划，扣除可用现货及已安排、未被占用的供料后，仍需新增 Φ8 铜杆合计 10 吨。车间一 25 日有 10 吨剩余产能、铜板足够，且能满足所有实际领用时点，则可在 25 日安排 10 吨，26—29 日不再为同一需求重复安排，而不是每天各排 2 吨。提前产出的铜杆先实际称重入总库存，车间二仍按自己的日计划分日领用。

本轮进一步澄清：若 25 日原来已经计划生产 6 吨，后续又有 10 吨已知铜杆需求，且相关计划均未开始、25 日也尚未到来，则可以将两份需求合并看作 16 吨，重新安排为 25 日总产 10 吨、26 日总产 6 吨。这里 25 日的 10 吨包含原有 6 吨，不能再额外叠加一次。无须纠结新增的某一份 10 吨需求是否恰好在一天完成。

- 检查的是车间一当天所有安排的合计产出，不超过当日配置的最大产能；不能因为尚未到生产日期就忽略特殊日期限产。
- 车间一原有已确认但尚未开始的安排可以参与整体重排；仍按既有流程预览合并后的计划及变化、人工确认后生效，不能静默改写。
- 已开始、已经完成或已有实际的部分保留，不能被合并重排覆盖，也不能通过减少历史计划掩盖已发生差额。
- 铜板不足、特殊日期产能不够或供料时点不满足时，应分开安排或提示风险，不能强制压到一天。
- 只合并已知、尚需补产的需求，不能因为日产能还有余量就自动增加没有需求依据的备库产量。
- 不要求每次凑满最高日产能才允许生产；需要少量铜杆才能按时供料时，仍应及时安排。
- 车间一集中生产不要求车间二同步集中加工，也不改变车间二一订单一规格的记录规则。
- 合并需求、移动日期及重新拆分后，总铜杆计划量和总铜板需求不得重复增加；相关预留引用或调整沿用同一批已确认用料需求。

本次确定的是按车间一整体已知需求统筹未来生产，而不是固定“某份需求最少天数”和“某份需求最早日期”之间的严格优先级。具体排程实现须遵守这些约束，不再为不影响供料的等价安排逐一增加业务选择题。

结合 7.2—7.3 已有确认，R04 的业务约束至此收口；具体排程算法和日内供料顺序的表达属于开发设计与场景验收，不要求用户继续选择不影响业务结果的等价算法。

## 8. 实际生产、每日称重与订单归属

### 8.1 生产事实

- 生产记录覆盖全部任务，再按具体任务查看实际过程，不能只针对示例订单。
- 记录实际开始、停止或结束时间、实际生产日期、经办人及异常说明。
- 车间一记录实际铜板投入及合格 Φ8 铜杆产出；车间二记录铜杆领用及合格铜丝产出。
- R12 已确认车间一实际投料记录同时登记本次实际铜板材料总金额，人民币元。相同投料只记一次，不因关联多个订单或后续多次铜杆称重而重复归集金额，详见 11.7。
- 一个日任务可以有多次实际记录，车间一可以多批完工入库。
- 已确认每天结束能够称重登记。当天多条记录只累计本次新增量，不将日末累计重量再次作为新增量重复入库。
- 未称重时显示待统计，不写零、不按运行时长估算实际产量。
- 补录按实际生产日期归属，录入时间另存；跨日分别保留每天的实际及计划差额。

### 8.2 同日多订单的实际归属

实际产量不能只存为车间当天一个总数，必须能识别其中多少属于哪个订单，以及多少尚未分配。

例如当天实际合格产量为 10 吨，其中订单 A 为 3 吨、订单 B 为 4 吨、未分配库存为 3 吨：

- 总产量只统计 10 吨，订单归属明细与未分配量之和应为 10 吨。
- 不能把 10 吨总量分别重复计给 A、B，也不能把未分配的 3 吨随意计入某订单进度。
- 车间二成品必须保留规格；多规格不能在没有明细的情况下混为一项成品库存。
- 原则上实际记录关联已安排任务及订单；合并生产或产生未分配量时，也应保留相应分配明细，不强制车间一一批只对应一张订单。
- 车间一实际产出仍先进入通用总库存。订单归属信息不能变成车间二必须选择来源批次的操作要求。
- R07 已确认成本随共用铜杆库存流转，订单实际领用时承担相应上游成本；未领用部分继续保留在库存，具体计价见 11.6。原始实际、领用及更正记录继续关联追溯，库存归属调整不重新增加产量。
- 车间一可以合并生产，并按 11.6—11.10 已确认的方法把成本经库存带入订单；总投入、产出、库存以及车间二已有订单任务物料记录继续保留。铜杆产出归属不直接累计为客户订单已经完成的合格铜丝量。

### 8.3 成品入库及分配

1. 合格铜丝称重后，按规格入库。
2. 对明确归属某订单的产出，优先满足该订单剩余需求并形成相应预留，不能超额占用订单不再需要的数量。
3. 超出该订单需要的部分、明确未分配的部分，成为同规格可用库存。
4. 已有库存分配、新增产出及交付分别保存，避免将同一批数量既当既有分配又当新增生产重复计算。
5. R12 已确认：同次同规格合格产出的总成本，按订单实际归属量与未分配量分开；公共成品携带自己的成本，按规格管理平均成本，后续确认分配给新订单时关联成本一次，不重新混算原订单已明确归属的部分，详见 11.10。

例如订单需要 10 吨，已有库存已预留 3 吨，新产 7.2 吨，则新增预留 7 吨，余下 0.2 吨可用；实际产量仍为 7.2 吨。

不建设废品处理，不记录不合格量，不以投入产出重量差自动生成废品数据。

## 9. 订单完成、交付提醒、取消与变更

### 9.1 完成及交付

- 按实际归属累计各订单已生产的最终合格铜丝数量，并结合已有成品分配判断剩余需求，不把车间一铜杆产量再加进铜丝完工量。
- 可用于订单交付的成品达到要求时，系统产生“已达到可交付条件”的提醒。
- 达到或超过要求量属于正常情况；提醒不等于已经交付，也不向设备发送停机指令。
- 不足时提示差额，由人决定后续追加安排，或填写原因后记录实际结束情况。
- 交付时登记实际数量、日期及人员，扣减实物和对应预留一次，保留记录。
- 保留原有必要数量和状态，不额外恢复“备货完成率”“交付完成率”两套独立指标。
- R15 已确认生产结果、交付情况及核算情况分别表达，不能用一个“完成”标签互相替代；不足量结束和库存直接满足等规则见 9.4。

### 9.2 取消

| 情况 | 处理要求 |
| --- | --- |
| 尚未开始执行 | 取消未执行生产安排，释放对应产能及库存预留 |
| 已经开始生产 | 由人登记实际停止原因、已发生投入和实际产出，不由系统控制停机 |
| 已产实物 | 沿用原确认规则：实物保留，不因取消删除；释放不再需要的订单预留，可供后续需求利用 |
| 共用铜杆任务 | 不能因取消一个订单而删除其他订单仍需要的共用安排，应重新检查剩余需求 |
| 历史记录 | 保留订单取消时间、原因以及全部实际和变更记录 |
| 取消后的成本 | R14 取消分支已确认：保留实际投入、产出和原始成本记录，可再用且尚未交付的合格成品携对应成本归公共库存，避免原单与后续订单重复承担 |
| 取消后的利润显示 | 取消单不显示利润，不套用原合同总金额减成本的正常订单公式，不因此推断取消后收入必为零 |

取消时如果停止产出尚未称重、记录未齐，沿用待统计或待核算，待补齐实际事实后处理；不新增“不明成本”业务。原合同金额及历史仍保留，不把所有已发生成本清零或直接认定全部损失。取消见 11.14、减量见 11.15，不足量结束按 9.4 已确认规则执行。

### 9.3 订单数量和交期变更

- 增量先检查可用成品，再对剩余需求重新评估库存、供料和产能。
- 减量释放多余预留，减少未执行安排，保留已产实物和已发生实际。
- R14 已进一步确认：减量后未交付且超出新需求的合格成品，携对应成本归同规格公共库存；合同总金额由人按新约定确认，需要时修改并留痕，不能直接按数量比例自动改金额。新金额未明确时不显示最终盈亏，详见 11.15。
- 改交期更新排序，重新检查受影响的后续安排，人工确认后生效。
- 已执行部分不可被重排覆盖；更正保存前后值、原因、时间及手填经办人。
- 需求数量不能通过普通减量降到已交付数量以下，应提示核查。

### 9.4 R15 已确认：生产、交付、核算分别显示

| 信息 | 已确认表达 |
| --- | --- |
| 生产结果 | 根据计划、实际及人工结束记录显示进展；正常生产结束与“不足量结束”区分，完全由库存满足的订单显示“无需生产” |
| 交付情况 | 成品实际备齐后显示“可交付”，实际足额交付后显示“已交付”；保留已交付量和要求量，不把生产结束当作已经交付 |
| 核算情况 | 金额未确认或成本未齐时显示“核算中”；满足对应金额和成本条件后显示估算盈亏，取消单仍不显示利润 |

- 可交付判断以已经确认分配给本订单的真实合格成品为依据，考虑已交付数量与剩余需求，不能只因为公共库有同规格货就同时承诺给多个订单。
- 仅由库存满足的订单，确认成品分配后可以直接显示“无需生产＋可交付”，不为了经过状态链而新增生产任务。交付和成本记录仍按实际保存。
- 生产结束、可交付、已交付和核算完成可以处于不同时间，例如“生产已结束、成品可交付、费用仍核算中”可以同时存在。

**不足量结束示例与规则：**以没有其他库存补足的订单为例，原要求 10 吨、实际完成 8 吨，人决定不再追加：

1. 人填写原因后，明确显示“不足量结束”，保留原要求 10 吨、实际 8 吨、差额 2 吨及结束原因，不把原要求改成 8 吨消除不足。
2. 已有 8 吨仍可用于该订单后续交付，按实际交付数量记录；不足量结束不等于取消，不自动把这些成品和成本转为公共库存。
3. 即便已将这 8 吨全部交出，仍保留原要求 10 吨、已交付 8 吨、不足 2 吨的结果，不能显示成已经足额履约 10 吨。
4. 依据人工决定不再追加的事实，按已有调整规则处理剩余不再执行的生产安排及不再需要的预留；已供该订单交付的成品不因不足结束而一律释放，其他订单共用需求不被删除。
5. 实际约定金额未确认或成本资料未齐时继续“核算中”；由人确认实际约定金额、成本齐全后，再按确认金额与该订单实际归集成本计算估算盈亏，不自动按原合同全额或按产量比例推算金额。

状态以保存的实际记录和人工业务决定为依据，更正沿用前后值、原因、时间及经办信息留痕，不通过修改状态标签虚构交付或抹去历史。系统只表达事实和结果，不控制现场生产。

### 10.2 总量与订单分摊的关系

原来的车间总量仍是计量来源。订单经营分析包含材料、能源成本分摊，不能整体恢复旧稿“能源一律不按订单归集”的排除口径。车间二按 R09、R10 执行；车间一相关成本按已确认方案随铜杆库存带入订单，不能直接按车间二当天订单产量分摊当天车间一全部成本。

订单分摊属于经营估算，不能把分摊结果表述为订单独立电表、水表直接测量的数据。能耗总量、分摊依据、单价和计算结果应能相互核对。

## 11. 订单成本与利润估算：铜杆成本随库存带入订单

### 11.1 必须交付的结果

完整目标是每个订单有简化成本口径下的估算利润或亏损结果，并能追溯其依据。车间一成本随铜杆库存、按加权均价带入订单，材料金额按 11.7 人工登记，已有铜杆初始成本按 11.8 录入；尚未填写的成本资料及未定依据仍须标出，不能以零填补：

| 信息 | 要求 |
| --- | --- |
| 合同总金额 | R11 已确认人工录入，人民币元；正常完成订单按合同总金额作为估算盈亏的金额依据 |
| 原材料投入及成本 | 人工登记每次实际铜板投入的材料总金额，作为铜杆入库成本的组成来源；订单计入铜杆领用成本后，不再另扣同一笔铜板成本 |
| 能源成本 | 能将与生产有关的用电、用水、煤气消耗按确定规则归集，再结合各项单价计算；车间二按 R09、R10，车间一能源成本随铜杆库存带入订单 |
| 估算利润/亏损 | 展示合同金额、纳入的成本和差额，注明采用的简化口径及数据完整程度 |
| 追溯信息 | 能查明统计期间、数量来源、分摊依据、单价及结果状态，不能只有一个无法解释的利润数字 |

概念关系为：

**正常完成且成本齐全的订单估算盈亏 = 人工录入的合同总金额 − 计入该订单的材料与能源总成本。**

这是按简化成本构成展开的估算关系式。对通过新生产满足的正常完成订单，铜板材料及车间一能源已包含在铜杆领用成本中，可等价按“合同总金额－归属订单的铜杆成本－车间二能源成本”汇总，不能再加一次上游成本。公共成品按 11.10 保留自己的成本；取消按 11.14 不显示利润，减量按 11.15 确认新金额，不足量结束按 9.4 确认实际约定金额、成本齐全后核算。

R11 已确认：正常生产完成且成本资料齐全后，才显示该订单的最终估算盈亏。生产中或成本未齐时，显示合同金额、累计已核算成本及“核算中”，不把阶段性差额当成最终盈亏。R14 确认取消单不显示利润、减量需确认新金额；R15 进一步确认不足量结束在实际约定金额确认且成本齐全后也可计算估算盈亏。本项不代替会计收入、税费或回款核算规则。

已有同规格公共成品满足订单的路径继续保留，按 11.10 关联成本、按 9.4 显示“无需生产＋可交付”，交付与核算分别表达；不再加一遍原有材料和能源，也不强行要求一条不存在的生产完工记录。

第一版采用本文明确的材料与能源简化成本，不另增人工、税费、运费、折旧等独立费用计算项；人工填入的实际材料总金额仍按其原始金额依据使用，不重复拆加费用。结果不标为完整财务净利润，后续扩大费用范围按需求变更处理。

### 11.2 能源分摊的明确范围与待定口径

- 车间二订单的电、水、煤气分摊权重及日能源取用范围已确认；车间一材料和能源成本计入合格铜杆库存，按 11.6 的入库加权均价随订单领用带入成本。
- 必须支持同一车间一天内多个订单共享能源消耗的估算分摊，并结合工业能源单价换算成本。
- 会议中的 30%/70% 是数值示例，不是固定比例；现在按 R09、R10 已确认的实际产量及当日能耗规则计算各日比例。
- **R09 已确认：车间二按各订单当天实际称重的合格铜丝产量确定分摊权重，不按计划量、最高日产能或运行时长代替。**在当日合格产出均已明确归属订单的常规场景，订单分摊比例为该订单当日实际合格铜丝量除以车间二当日实际合格铜丝总量。
- 例如当日订单 A 实际合格产出 4 吨、订单 B 为 6 吨、总产量 10 吨，则 A 的分摊比例为 40%、B 为 60%。只使用车间二产出，不混入车间一铜杆量。
- **R10 已确认，仅适用于当前车间二口径：有合格产出日，使用车间二当日实际计量的能源总量作为分摊总量，包括该日待机、空闲期间的消耗，不额外拆分生产和待机能耗。**
- 订单份额 = 该项当日能源总量 × 该订单当日实际合格铜丝量 ÷ 车间二当日全部实际合格铜丝量。分母包含未分配成品；未分配部分保留自己的能源份额，不转摊给已有订单。
- 例如当日用电 1000 kWh，A 产 3 吨、B 产 4 吨、未分配成品 3 吨，则 A 分摊 300 kWh、B 分摊 400 kWh、未分配部分保留 300 kWh。水、煤气有对应计量时采用相同规则，再结合各自单价换算费用。
- 确认当天没有合格产出时，实际能源消耗单独记在车间，不分摊给订单；尚未称重或记录未齐不等于无产出，先待核算。
- 当天未达到最大日产能但实际有合格产出时，仍按全部实际合格产量分摊当日计量总耗，不用最高日产能作分母，也不按未用产能虚构额外产出。
- 无实际称重、总产量尚未确定或为零时，不强行计算产量比例；无对应能源计量时，不以零代替其分摊结果。沿用缺数据、待统计与确认为零分别呈现的原则。
- 两车间分别处理，不能先把铜杆和铜丝吨数相加，再据此分摊全厂能耗。车间一跨日未产出及全天无实际生产的待机费用归集，用户已明确当前暂不考虑，按 11.12 处理，不因 R10 已确认就自动照搬车间二规则。
- 同一段实际能源成本不可重复计入多个订单；订单、未分配产出及无产出日单列部分应能核对实际总量和费用。公共成品后续分配按 11.10 的同规格公共均价关联成本，不能再重复增加其原有能源费用。

### 11.3 通用铜杆及成品库存的成本衔接

**R07 已确认：车间一实际铜板成本与能源成本先计入合格 Φ8 铜杆库存，订单领用时按库存均价带入对应上游成本。**车间一同一次生产的投入、产出和能源总量分别记录一次；车间二订单、任务、领用及产出记录继续保留，不能将同一份总成本重复归给多个订单。

完整核算的订单明细需要追溯铜杆领用数量、均价、上游材料及能源成本构成、车间二能源分摊量及成本。属于共用生产后分配的数量或金额，应标明依据，不能表述为该订单在车间一独立仪表实测的消耗；各订单、未分配部分和剩余库存应能核对总量和总成本。

通用库存模式保留，不能为核算而强制操作人员选择来源批次。恢复成本对齐后，要覆盖以下场景：

1. 车间一合并生产时，实际铜板成本和应归入合格铜杆的车间一能源成本先进入铜杆库存，按 11.6 计算均价，不强制生产时逐单拆分。
2. 车间二为订单实际领用时带入对应上游成本，再增加该订单按 R09、R10 分摊的车间二能源成本。
3. 订单直接使用既有公共成品、没有新生产时，按 11.10 关联相应数量的公共成品平均成本，不能默认零成本。
4. 正常生产未分配或超产转为可用库存时，按实际合格产量比例保留对应成本，只有同规格公共部分参与均价，原订单已明确归属的成本不混算。
5. 取消按 11.14 保留历史且不显示利润，减量按 11.15 确认新金额；可再用成品及对应成本转公共库存，避免前后订单重复承担或漏算。

库存价值中已经包含的铜板材料和上游能源成本，应衔接到订单成本构成；不得在计入铜杆或成品领用价值后，再次全额加算同一材料或能源成本。成本归属调整也不得重新增加实际投入量或实际能耗。

铜杆交接按 R06 的实际交出重量扣总库存，接收重量及差异另记。R12 已确认，明确用于某订单的一次领用按交出重量乘铜杆均价计入该订单上游成本，不能再就交接差异加一笔费用。多订单一次交接不得因此擅自平均拆分差额，应保持实际明细可追溯，本次不另定多订单差异分配算法。

这些是完整订单利润目标的设计边界。铜杆均价、实际材料金额、初始库存、交接差异及正常生产公共成品成本均已确认；不能将所有成品混池均价后重算已有明确归属订单的生产成本。资料未齐按 11.11 待核算、补齐后更新并留痕。车间一跨日未产出及全天无生产的特殊费用归集已由用户明确暂不考虑，不作为 R12 继续追问的事项。

### 11.4 结果完整性及增强功能

- 合同金额、材料成本、能源单价或必要计量缺失时，应显示待补充、核算中及具体缺项，展示已核算成本，不显示最终估算盈亏，不能把未知成本当零后宣称盈利。
- 已知数据仍保留可查；缺实际资料或遇到明确范围外场景时按待核算处理，不因此整体删除订单成本及估算盈亏功能。
- 简单原因分析可以作为增强功能，例如展示订单价格偏低、原材料成本较高、能源成本较大等可能因素。
- 原因分析尚不要求复杂算法或 AI 自动推断。完整利润结果仍是建设目标，车间一成本恢复对齐后仍不能用零成本填补尚未核算的部分。

### 11.6 R07、R12 当前范围已确认：铜杆库存加权均价

本轮再次明确成本组成：**该次合格 Φ8 铜杆入库总成本（元）＝实际铜板材料成本（元）＋应归入该次铜杆的车间一能源成本（元）。**此处能源为车间一的电、水、煤气费用，不含车间二加工能源；铜板成本是必要组成，不能遗漏，也不在订单领用铜杆后重复加算。

1. 实际投入的铜板成本与归入相应合格铜杆的车间一能源成本，构成该次铜杆入库成本；不以“计划铜杆量 × 1.05”直接替代实际材料成本。
2. 新铜杆与原有铜杆合并后，平均每吨成本 = `（入库前铜杆库存成本＋本次铜杆入库成本）÷（入库前铜杆实物吨数＋本次实际合格入库吨数）`。
3. 均价基于库存实物总量，不能只用可用量而排除已预留的实物；预留不减少实物或提前结转成本。
4. 订单实际领用时，按实际交出重量乘适用库存均价带入对应上游成本；铜杆库存数量沿用 R06 的交出重量，接收及差异另记。明确归属一个订单的交接差异成本已按 11.9 确认，不重复增加费用。
5. 订单铜杆成本已经包含上游铜板与车间一能源，后续只另加该订单的车间二能源等已确认成本，不重复加计相同上游成本。

本轮澄清：铜板金额是计算铜杆成本的原始组成，并非订单核算时另加的一项成本。用户随后已明确认可实际投料时人工填写材料总金额，见 11.7；此前提出的铜板库存独立均价方案未被选用，不作为第一版必做模块。R01 铜板数量库存及 R02 备料计划继续保留，不因此增加原材料采购结算流程。

以下为说明算法的示例，不是企业实际采购价格或期初成本：

| 项目 | 铜杆数量 | 成本金额 |
| --- | --- | --- |
| 原有库存 | 10 吨 | 60 万元 |
| 新入库 | 10 吨 | 64 万元 |
| 合并库存 | 20 吨 | 124 万元 |
| 合并后均价 | 每吨 | 6.2 万元 |

### 11.7 R12 已确认分项：实际铜板材料总金额人工登记

- 车间一登记实际投料时，人工填写本次实际投入铜板的材料总金额，单位为人民币元；与已有实际投入吨数关联保存。
- 此金额是整次实际投料的材料总额，不是每个客户订单单独填写的金额。多订单合并生产只记一次，同一实际投入也不因后续多次称重再次加一笔成本。
- 系统用该材料金额加上应归入相应铜杆的车间一能源费用，计算合格 Φ8 铜杆入库成本，再按 11.6 进入铜杆库存均价。
- 第一版不要求另建铜板库存金额及加权均价账；铜板数量期初、入库、预留和领用规则继续按 R01 执行。
- 1.05 仍仅用于计划铜板需求量，不用其推导实际材料金额。未填写实际材料金额时标待补充或待核算，不当作零；实际领用数量也不以金额反推替代。
- 能源费用未齐时仍按待核算或暂算处理，单价按本轮已确认的 11.13 维护；交接差异成本按 11.9，补齐及更正按 11.11 执行。

### 11.8 R12 已确认分项：初始库存及初始成本

| 库存对象 | 已确认方式 |
| --- | --- |
| 系统启用时已有 Φ8 铜杆 | 首次人工登记实际吨数及对应库存总成本，作为后续铜杆数量和成本的初始余额 |
| 成品铜丝 | 第一版初始默认没有成品铜丝，初始数量为零、库存价值为零；后续生产再按规格正常入库 |

- 用户认可首次人工登记数量和总成本的方式，并补充成品初始默认无货；因此初始化不要求为不存在的各规格成品填写虚构金额，也不预置演示成品库存。
- 真实没有成品所以初始库存价值为零，与已有库存但成本未知是两种情况。有铜杆数量但总成本不清楚时，可先登记数量、成本标待补充，相关订单维持核算中，不以零代替。
- “初始默认没有”不影响今后成品生产、库存分配和交付，也不将成品库存永久限定为零。若初始化确有实际成品需登记，沿用已认可的按规格登记数量和总成本方式，不把这一可选情形作为默认初始化要求。
- 铜板数量初始登记仍按 R01；本项不重新引入铜板库存金额及加权均价账。后续公共成品计价另按本轮已确认的 11.10 执行。

### 11.9 R12 已确认分项：订单承担交出铜杆的全部上游成本

- 本次领用全部用于某一订单时，该订单按实际交出吨数乘以适用铜杆平均单价承担上游成本，保持出库数量与出库成本的计价依据一致。
- 例如全部为 A 订单领用，交出 10 吨、接收 9.8 吨：A 的上游成本按 `10 吨 × 铜杆均价` 计算，接收记录仍为 9.8 吨，差异仍为 0.2 吨。
- 0.2 吨的成本已经包含在这次 10 吨出库成本中，不再另扣库存、不再增加损耗费用，也不另建废品或不合格量记录。
- 超出 5% 时需填写原因后人工放行的已有规则继续执行，不能通过改重量消除差异。
- 交接按接收任务保留明确的订单、交出及接收明细。一次实际交接涉及多项任务时按明细分别记录、核算和汇总；明细未齐则待补充，不按未知比例自动拆分同一份出库成本，不把它全额重复计给多个订单。

### 11.10 R12 已确认分项：正常生产的公共成品成本

- 同一次、同规格铜丝生产的总成本由对应铜杆成本及车间二能源成本组成。按该次实际合格铜丝数量，将总成本分给明确归属订单的部分和未分配、超产的公共部分，不能让原订单先全额承担后又给新订单加一次。
- 例如实际合格产出 10 吨、总成本 60 万元，其中 A 订单 8 吨、未分配 2 吨：A 承担 48 万元，2 吨公共成品保留 12 万元成本，合计仍为 60 万元。
- 公共成品按规格管理；均价只使用仍未分配的同规格公共数量及对应成本，新公共部分与该自由份额合并计算均价。已明确归属订单的成品不混入此池，不因后来公共库存新增而重新平均原订单的成本；这与铜杆均价基于全部实物量的口径应区分。
- 新订单正式分配公共成品时，按分配数量及适用公共库存均价关联对应成本，只计一次；不重复增加原有铜杆、铜板、车间一或车间二能源成本。
- 正式分配的份额退出自由公共成本池，但仍保留在实物库存总量和总价值中；分配仅改变可用、预留及成本归属，实际交付出库时才同步扣除对应实物和库存成本，不能在货物还在库时先减库存总价值。
- 成本关联保留来源和份额，原始投料、领用、生产与能耗事实不因归属调整重复生成。已归属成本仍可因原始数据补齐或有记录的更正而按 11.11 修正，不将其解释成永远禁止合理补算。
- 本节确认正常生产的未分配、超产成品；取消订单的后续确认另见 11.14，不因成品转公共库存就清零原始成本发生记录。

### 11.11 已有待核算及更正原则的落实

- 材料金额、能源费用或其他必要成本数据未齐时，仍可记录真实生产、称重、入库和领用等事实；相应金额标待核算或暂算，不用零冒充完整成本，不因缺成本字段向现场设备施加生产控制。
- 补齐原始成本资料后，应补算受影响的库存和关联订单结果，保存原值、调整值、依据、时间及经办信息，不能静默覆盖历史结果或重新增加实际数量、投入与能耗。
- 补齐或更正历史数据，与后续正常新增采购、生产入库是不同操作；不能将后来的新价格追溯套给之前已实际发生的领用。均价、补差的具体执行顺序由开发设计保证与这些业务结果一致，不另要求用户选择技术算法。
- 本节落实已有缺数据待核算、实际与成本分开及更正留痕规则，不将用户明确暂不考虑的车间一特殊成本归集方案当作已经确认。

### 11.12 用户明确暂不考虑的车间一特殊成本场景

本轮提出后，用户明确要求当前暂不考虑以下情况，第一版不要求实现其自动成本归集方案：

1. 单次车间一生产跨日，已投入铜板但当天尚未产出合格铜杆时，材料和能源如何跨日累计、以后如何分配。
2. 车间一全天没有实际生产、只有待机能源消耗时，这部分费用如何归集或分摊。

这一范围决定不代表已认可此前提出的累计或车间单列方案，也不构成所有生产必须当天完成的新限制。实际开始、停止、称重和能源事实仍可按已有规则保存；无法按已确认口径完整核算的费用沿用待核算，不自动当作零成本或强摊给其他订单。以后若恢复这两类成本场景，再集中确定具体规则。

此处只针对车间一，不撤回已经确认的车间二 R10：有产出日总耗含待机空闲、未分配成品保留份额、确认无产出日单列。

### 11.13 R13 已确认：能源单价维护、生效及历史更正

| 能源 | 人工维护的单价单位 |
| --- | --- |
| 电 | 人民币元/kWh |
| 水 | 人民币元/m³ |
| 煤气 | 人民币元/Nm³ |

- 用户在页面填写各类能源单价及生效日期；使用与实际能源单位匹配的价格计算相应费用，不自动抓取市场价格作为企业价格。
- 按实际用能日期取当日适用的有效价格，不用订单录入日期或补录当天的新价格替代历史用能价格。
- 例如新价格从 11 月 1 日生效，10 月能耗仍按其对应旧价计算；新增价格不自动改变以前已经核算的结果。

### 11.14 R14 已确认分支：取消订单保留实际和成本，不显示利润

- 取消订单保留已发生的实际投入、产出、领用、能源和成本记录，不能删除历史或直接把已发生费用清零。
- 仍在库、尚未交付且可再用的合格成品，解除原订单预留，携带对应成本归入同规格公共库存，后续分配按 11.10 执行。
- 原订单保留成本发生及转为公共库存的关联记录；同一份成品成本不能既由原订单承担，又在后续订单中再算一次。“归公共库存”不产生新的物理入库，不增加总实物或总成本。
- 取消时实际停止情况、合格产出等记录未齐，仍按已有待统计、待核算规则补充；所谓未明确是原始实际记录未齐，不新增专门的“不明成本”模块，也不把未知去向自动认定为损失。
- 取消单不显示利润，不能用原合同全额减去当前已发生成本显示盈利。原合同金额保留为历史信息；不由此设定实际取消收入为零，也不新增退款或补偿结算规则。
- 已交付事实及成本不因取消回滚，已实际领用的铜杆不能因取消自动变回现货；继续按真实发生记录处理。
- 未执行计划及未领用预留释放、共用铜杆任务保留其他订单需求等沿用第 9 节已有规则。
- 减量的后续确认见 11.15，不足量结束见 9.4；不能将取消单不显示利润、成品转公共库存的规则自动套用到不足量结束。

### 11.15 R14 已确认分支：减量后确认金额及多余成品成本

- 例如需求从 10 吨改为 8 吨，释放多余的未执行安排、产能和未实际领用预留；保留全部实际生产、领用、称重、交付及成本记录。
- 已产出、尚未交付且超出新需求的合格成品，解除多余订单预留，携带对应成本归入同规格公共库存。原订单保留仍需部分的成本与全部历史，不重复入库、不增加总实物或总成本。
- 合同总金额由人按新的实际约定确认，需要时修改并记录前后值、原因、时间及经办信息。减量不表示金额必然按同一比例下降，也允许按约定确认原金额不变，不能由系统直接乘数量比例。
- 新金额未明确时不显示最终盈亏，继续显示数量、合同金额记录、已核算成本及待确认信息。金额明确后，按订单实际满足方式执行：需要生产的保留实际生产结束和成本齐全条件，库存直接满足的按 9.4 显示无需生产、不补造完工记录；金额和相关成本齐全后再显示最终估算盈亏。
- 不得通过普通减量把要求数量降至已交付数量以下；已交付事实及其成本不回滚，共用铜杆安排仍须保留其他订单需要的部分。
- 本项沿用订单修改和保存操作，不增加独立金额审批流程；不足量结束的结果和金额处理按 R15 已确认的 9.4 执行。

## 13. 系统一：异常提醒、巡检及维修

### 13.1 阈值和提醒

- 监测参数的报警阈值及触发条件支持页面配置，不应全部固定在代码中。
- 普通参数满足配置的持续异常条件后产生提醒；短暂超限不直接认定设备故障，不自动生成报修或维修单。
- 正常范围、报警范围、持续时长等应区分，会议未确定统一秒数，不能把演示值写成默认工业标准。
- 保留此前已确认的例外：关键参数允许配置为立即提醒。立即提醒仍不等于判定故障或正式报修，所有提醒均由人判断是否需要维修。
- 持续同一异常避免重复新增提醒；测点离线独立提示，不直接判为机械故障。
- 可以标记已知悉或由人决定暂不报修；记录恢复不等于维修完成。
- 阈值变更用于后续判断，保留变更前后值和时间，不改写历史事件。
- R16 已确认同一异常去重、恢复后再次触发及阈值变更衔接方式，详见 13.3；不因此新增一个写死的恢复等待秒数。

### 13.2 报修及处理

**异常提醒/人工巡检发现问题 → 人判断需要报修 → 自动带入报修草稿 → 补充说明及照片等 → 人工正式提交 → 审核 → 维修 → 验收。**

- 自动带入设备、测点、异常时间、异常值和异常内容，允许补充照片、故障说明及人员信息。
- 最新会议明确增加“草稿可编辑、人工正式提交”阶段；不能在提醒产生时或仅打开报修内容时就直接进入已正式提交的待审核状态。
- 巡检人工录入设备、时间、巡检人、内容、结果和说明等，异常可以进入同一报修流程；暂不自动生成每日、每周周期巡检任务。
- 信息不完整可以审核退回，保存意见，补充后再次提交。
- 无需维修或重复报修，填写原因关闭并保留记录。
- 验收不通过退回同一维修单继续维修，保留每轮维修和验收，不另建一张单覆盖历史。
- 参数恢复正常不能自动关闭维修单，只有完成相应人工处理流程才改变工单结果。
- 运维统计沿用巡检及异常次数、维修待办和完成量、处理用时、设备报修次数及期限提醒等已确认框架；报修次数不等于实际故障次数，具体口径统一定义。

### 13.3 R16 已确认：异常事件的持续、恢复及规则变更

| 情况 | 已确认处理 |
| --- | --- |
| 同一测点、参数按同一规则持续异常 | 保留同一个异常事件，更新持续过程，不因采集、刷新或再次查询而重复新增提醒 |
| 异常恢复正常 | 保留原异常记录并登记恢复时间；恢复后的再次异常，重新满足触发条件才生成新事件 |
| 修改阈值等触发规则 | 只结束受影响的当前异常事件，注明“因规则变更结束”，保留旧读数、旧阈值及原记录；从下一条有效数据按新规则重新判断 |
| 普通参数重新判断 | 按新规则重新计算持续异常时间；未满足持续条件的短暂超限不直接生成新维修单 |
| 关键参数重新判断 | 沿用已确认的可配置立即提醒规则，不因为普通参数重新计时就取消关键参数即时提醒 |
| 已存在维修单 | 读数恢复或规则变更均不自动关闭，仍走人工审核、维修、验收流程 |

- 记录异常开始、触发提醒、实际恢复或其他结束原因，区分“自然恢复”与“因规则变更结束”；不能把修改阈值当作设备已经恢复正常的证据。
- 规则修改保存前后值、时间和经办信息；旧事件的判断依据不被新配置覆盖，不批量结束无关测点或参数的提醒。
- 参数异常提醒、已知悉等人工处理、维修单状态分别保留，不互相冒充。再次异常可以形成新事件，既有维修关联和处理历史仍可追溯。
- 采样去重、事件边界和防抖的具体实现应满足上述结果及已有配置条件；本轮未新增统一的恢复等待时长或固定工业阈值，不自行把演示秒数当成企业标准。
