# 系统二 · 订单与计划页面与交互规格

## 1. 模块导航

侧栏使用已有「订单与计划」。模块内提供「订单」「库存」「产能」「日计划」四个入口，默认选中「订单」。方案编辑器从订单评估或有效计划进入，打开时保留来源页筛选。成品分配及交付从订单详情进入。

| 入口 | 页面内容 | 接口组 |
| --- | --- | --- |
| 订单 | 列表、新建、详情、变更记录、成品归属及交付 | S2-O、S2-D |
| 库存 | 物料规格、三类库存、余额详情、期初、铜板到货、流水、预留和未来供料 | S2-I |
| 产能 | 两车间普通日产能、日期覆盖配置、占用和风险 | S2-C |
| 日计划 | 两车间有效日任务、方案详情及版本历史 | S2-P03–P05、P07 |
| 方案编辑 | 评估结果、人工编排、供料关系、影响预览和确认 | S2-P01、P02、P06 |

## 2. 订单列表与详情

### 订单列表

- 查询字段为订单号或客户关键词、铜丝规格、交期范围、生产结果、交付结果、核算状态。默认按交期、录入时间、订单 ID 升序。人工优先级单独标识，联合评估时允许急单跨交期优先试排。
- 列表列出订单号、客户、规格、需求吨数、交期、优先级、生产／交付／核算结果和金额是否已确认。点击订单号打开详情，返回后恢复筛选及分页。
- 「新建订单」打开表单。勾选多张仍有待安排需求的订单后可发起「联合评估」。以订单 ID 保存勾选项，展示已选数量和移除入口。筛选条件变化时清空选择，避免误带入之前的订单。评估时仍由服务端判断选中订单的最新状态和版本。
- 取消或已足额履约的订单可查询及查看历史。没有待安排需求时，评估动作置灰并显示原因。已有实际但仍有剩余需求的订单，允许评估剩余范围并展示保护项。

### 新建订单

| 字段 | 输入规则 |
| --- | --- |
| 订单编号、客户名称 | 必填。保存时校验订单编号唯一。内部订单 ID 由服务端生成。 |
| 铜丝规格 | 必选一项启用的铜丝物料，显示规格及编码。 |
| 需求量 | 必填，大于零，单位吨，最多三位小数。 |
| 交付日期 | 必填，业务日期。到期或逾期按日期明确标识。 |
| 合同总金额 | 人民币元，最多两位小数。留空显示待补，明确录入的零与待补单独表达。金额确认使用单独的明确选项。 |
| 计划用杆总需求 | 有当前剩余加工依据时可填，单位吨，最多三位小数。用户不确定、成品可满足或尚未确定加工范围时可暂留空，待评估草稿补齐或重核。 |
| 经办人 | 手填必填。 |

「保存订单」调用 S2-O02，成功后打开订单详情。提交中的重复点击合并，字段错误定位到输入项。新建保存后由用户自己点「评估排产」。

### 订单详情

- 摘要区显示原需求、已安排尚未生产量、待安排量、实际新生产、已分配成品、已交付、剩余可交付量和不足量差额。数量各自标明含义。分别显示生产、交付、核算三项结果。
- 「评估排产」发起当前订单的评估。「改期」「修改资料」使用 S2-O04，「调整优先级」使用 S2-O05，「增减量」「取消订单」「确认金额」分别使用 S2-O07、O08、O09。改期、增减量和取消界面提供可选的影响预览 S2-O06，列出受影响任务、可释放份额和保护的实际。
- 详情中提供成品分配、交付记录、变更记录与相关计划链接。生产结束和不足量结束进入「生产记录」，核算详情进入「生产与能源统计」。
- 缺用杆依据、缺金额、缺库存或有配套计划风险时在对应区块显示。变更发生版本冲突时保留输入，允许查看当前版本后再明确提交。

## 3. 评估与人工编排

### 发起评估

单单与联合评估使用同一入口表单，展示所选订单编号、规格、剩余需求、交期和评估区间。默认从当前业务日起至所选最晚交期，最晚交期早于今天时默认截止今天并标出逾期风险。用户可在发起前调整区间。带订单和需求范围版本调用 S2-P01。评估内部按合格同规格库存、剩余加工量、用杆依据、现货、未来供料、铜板、两车间产能和交期依次核对。

| 评估结果 | 页面进入方式 |
| --- | --- |
| 成品足够 | 展开成品分配明细，展示每张订单拟分配的库存和确认后的预留。生产任务区域显示无需新增任务。 |
| 可安排 | 将建议任务、顺序、供料关系和成品分配带入草稿，用户可以调整。 |
| 需要调整 | 打开同一草稿，带入可用安排和缺项，直接编辑。缺项包括欠缺量、适用日期、受影响订单和可执行的下一步。 |

### 草稿中的工作区

| 区块 | 显示及可编辑内容 |
| --- | --- |
| 订单与成品 | 各单原需求和交期、已生效归属、拟分配、实际合格产量、继续有效的已安排尚未生产量、本次安排量、保存后仍待安排量，以及用杆总需求和范围依据。后续评估或编排只安排仍待安排的部分，继续有效的任务量不能重复排入。成品分配影响当前加工范围时，提示重核用杆总需求。 |
| 两车间日计划 | 日期、有效产能、既有占用、拟安排、剩余或超出。可增删未生效任务，改日期、同日顺序、计划合格产量和车间二计划用杆。分别显示车间一合格铜杆和车间二合格铜丝。 |
| 库存与供料 | 分开列出现货、拟预留、有效预期供料和净补产。车间一新增铜板量由服务端计算。给供料关系选择源任务、目标任务和数量，同日时明确先入库后领用。 |
| 变更影响 | 已生效任务及其预留的旧值与拟改值。已有实际或已开始的任务展示保护原因。重排范围内的其他关联订单也要显示。 |
| 确认区 | 经办人、原因、待安排量、待处理问题、提交状态。预计延期时列出受影响订单、原交期、预计备齐日期及原因，未排足时将尚无法确定的备齐日期标为待定。一次人工确认调用 S2-P06。 |

S2-P02 用于读取人工编排上下文、查看既有方案、刷新草稿依据，以及 P2 联调阶段手工编排。正式新单和多单路径从 S2-P01 进入。原草稿需要补用杆、修改任务或复核库存在原编辑器操作。

### 保存、退出与冲突

1. 编辑阶段校验必填、吨数格式、日期与顺序疑点。本地规则只能提示可判定的问题。库存和产能是否合法由服务端确认事务判断。
2. 「确认保存」提交当前草稿、版本、经办人和原因。用户可在此次确认中接受已提示的预计延期，保留原交期并保存可执行方案。服务端仍校验库存、产能和供料。成功后显示生效方案、任务、预留和成品分配，可返回订单或打开日计划。全由成品满足时可查确认凭据，日历不产生生产任务。
3. 发生 409 时保留全部编辑内容并突出相应订单、日期、库存或供料关系。用户可刷新依据、查看有效方案并在草稿内核对后重新提交。网络中断且提交结果未知时，原内容重试沿用同一请求 ID。
4. 暂时查看库存或产能时，在当前页面会话保留草稿。采用模块内详情链接或新标签页查看补录结果，返回草稿后刷新依据。关闭或明确放弃时丢弃未保存编辑，已有有效版本及预留继续生效。

只排到部分需求时，也可确认本次可执行的安排。例如，订单要求 10 吨，本次排到 6 吨，确认后按该 6 吨的任务和对应物料需求建立预留，剩余 4 吨显示待安排。保存后订单仍要求 10 吨，原交期保留，实际合格产量仍按称重记录显示。后续编排保留已开始或有实际的任务及其原计划，继续有效的计划量只计一次。

## 4. 库存、产能、日计划与交付

| 页面 | 操作规格 |
| --- | --- |
| 库存 | 按铜板、Φ8 铜杆、合格铜丝规格筛选。显示实物、预留和可用，未来供料另列。空库存区分尚未登记与确认零库存。期初录入物料、数量、业务日和经办人，适用时录入总成本。铜板到货登记实际数量、日期、经办人。详情可查流水、预留和更正。 |
| 物料规格 | 订单选择启用铜丝规格。库存页可维护铜丝定义，显示编码、名称、规格与启停用。已有引用的规格核对历史影响，纠错时按接口限制保留原物料身份。 |
| 产能 | 按车间和日期范围查看普通值、特殊值、有效值、占用量和剩余或超出量。普通产能独立修改，停产用特殊日期填零。设置或撤销后展示受影响的未来计划。 |
| 日计划 | 按范围、车间、订单查看日任务，稳定显示同日顺序、合格产出目标、用料和供料风险。点击查看生效方案、历史版本或关联生产实际。允许从有可替换未开始任务的方案进入重排草稿。 |
| 成品分配 | 详情内查本订单已归属、剩余和已交付份额。后续追加分配只使用同规格可用公库。已随方案确认的分配直接回显。 |
| 实际交付 | 详情内显示已分配未交付量、实际已交付量与不足差额。登记实际交付日期、吨数和经办人，可分批。数量不可超过该单可交量与真实库存。更正从对应交付记录进入，说明原因并展示影响。 |

## 5. 状态、缺项和失败的展示

| 信息 | 页面口径 |
| --- | --- |
| 生产 | 按任务与实际显示待安排、已安排、生产中、生产结束、不足量结束、无需生产等。取消记为订单决定。保护历史生产进展。 |
| 交付 | 依据分配与实际交付区分尚未备齐、可交付、部分交付、已足额交付。已将不足量成品交完时仍展示未足额和差额。 |
| 核算 | 显示待补金额、待核算及已核算等状态。缺成本时保留数量业务。取消单显示取消及已发生事实。 |
| 读取错误与空态 | 加载、正常空列表及读取失败分别显示。失败提供重试，未知数量用待补或待统计表示，确认为零的数据按单位显示。 |
| 写入错误 | 400 定位字段并保留输入。404 提示对象已不存在并可返回列表。409 保留编辑和当前版本信息。服务不可用时提示重试，结果未知的写入须按原内容和原请求 ID 重试。 |

状态码、错误结构和版本语义以[接口开发规范](系统二-订单与计划-接口开发规范.md)为准。具体数量和异常输入见[开发任务与验收](系统二-订单与计划-开发任务与验收.md)。
