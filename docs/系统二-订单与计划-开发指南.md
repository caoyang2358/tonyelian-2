# 系统二 · 订单与计划开发指南

系统二的「订单与计划」从客户订单出发，统一管理可用库存、两车间产能、方案编排、计划确认和实际交付。本文是该模块的开发入口。当前工作覆盖设计文档，业务功能按验收清单实施。

## 已确认的操作入口

- 「订单与计划」默认进入订单列表。在模块内打开库存、产能和日计划，交付从订单详情进入。
- 订单保存独立完成。单单从详情发起评估，多单从列表勾选后发起联合评估。
- 成品足量、系统建议与需人工调整均进入同一方案编辑流程。用户只确认保存一次，任务、对应预留和适用成品分配同时生效。
- 已生效任务供「生产记录」读取。库存和交付事实供「生产与能源统计」核算，三处以同一业务 ID 关联。

## 开发顺序

先完成订单、物料、期初及到货、库存查询和产能维护。随后实现统一草稿和原子确认，串通实际投料、铜杆入库，再完成成品分配、交付与订单变更。自动联合评估复用同一个草稿和确认接口，最终验收覆盖自动建议与人工调整两条路径。

## 文档采用的实现约定

- 评估日期默认从业务当天到所选订单最晚交期，由用户在评估前调整。联合评估时，人工标记的急单可跨交期优先试排。同一优先级内按交期处理，用户仍可在方案草稿人工调整。
- 一个已确认的加工范围分成多天时，自动建议按各日产量分摊已确认的用杆总量，并在公斤精度下保持总量。剩余加工范围变化后由人重核总量。
- 期初总成本拟作为期初流水的原始金额保存，相关字段由实施阶段的新迁移补齐。库存及计划确认统一使用请求号重放与跨方案一致的加锁顺序。

## 实施资料和边界

- 普通日产能初值 10 吨/天属于系统可调整参数。现场产能、在用铜丝规格、库存期初及成本需由项目组录入或核实。
- V4–V6 已有业务表。现有表与接口之间仍需落实字段映射和少量持久化缺口。涉及结构补充时按数据设计新增迁移并与其他成员协调编号。
- 本模块记录计划和业务事实。采购流程、现场设备控制、真实能源计量和订单盈亏计算分别按需求基线的范围及所属模块处理。
