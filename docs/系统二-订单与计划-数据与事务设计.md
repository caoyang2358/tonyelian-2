# 系统二 · 订单与计划数据与事务设计

本文面向订单、物料库存、产能、排产、成品分配和交付的实现。以[需求对齐稿](系统二-订单与计划-需求对齐稿.md)、[接口清单](api/订单库存排产接口清单.md)和[需求基线](需求基线.md)为依据。下文列出主分支已有的表结构和本模块拟采用的实现。业务页面及接口仍待开发。

## 1. 数据映射

| 业务与接口 | 现有物理存储 | 实现时遵循的约定 |
| --- | --- | --- |
| 订单及变更 S2-O | V4 `p2_customer_order`，V2/V9 `p2_change_log` | `order_id` 是内部身份，`order_no` 是唯一业务编号。铜丝规格关联 `wire_material_id`。分别读取生产结果、交付结果和核算状态。基本资料、数量、取消、金额确认有各自的命令边界。 |
| 物料、余额、期初、到货及流水 S2-I01–I12 | V4 `p2_material`、`p2_stock_balance`、`p2_stock_movement` | 复用固定的铜板、Φ8 铜杆及按规格定义的铜丝。已有物料编码及类型内规格唯一约束。期初和到货以原始库存流水为记录根，期初原始成本见第 3 节。 |
| 预留及供料 S2-I13、I14 | V4 `p2_stock_reservation`、`p2_supply_commitment` | 预留占用现货。供料承诺追溯到供料任务、用料任务和需求键，兑现前始终单列。 |
| 日产能 S2-C | V4 `p2_workshop_capacity`、`p2_capacity_override` | 当前默认每车间 10 吨每天。普通值为正，特殊日可设为零。特殊日按车间和日期唯一，撤销标为 `active=false` 并留痕，查询回退普通值。 |
| 评估上下文、生效方案、任务日历 S2-P | V4 `p2_plan`、`p2_plan_task`、`p2_task_order` | 评估和草稿读取现状。一次确认后才写方案、任务及关联。接口 `taskId` 对应 `task_id`，`demandId` 对应 `demand_key`。临时任务键在确认事务内映射为实际任务 ID。 |
| 成品归属和交付 S2-D | V5 `p2_finished_allocation`、`p2_delivery`、`p2_delivery_item` | 成品归属一对一关联预留。交付主记录关联一笔实物出库流水，明细列出核销的归属份额。 |
| 生产实际和成本来源 | V5 `p2_plate_input`、`p2_output_record`、`p2_rod_handover`。V6 `p2_cost_run`、`p2_stock_cost_ledger`、`p2_order_cost_item` 和能源表 | 生产事实和核算模块分别持有各自的写入口。订单与计划通过共享库存能力和事实关联完成数量流转，并按适用成本版本展示成本结果。 |
| 请求重放与审计 | V2 `p2_request_result`、`p2_change_log`，V9 补充的审计版本及请求号 | 用请求号关联同次写入及其留痕。操作人、原因与版本随业务写入保存。 |

一期 `dim_workshop`、工序和单位沿用现场编码与身份，从二期统一参考接口读取。项目目前只在 V4 预置两种固定物料和两个车间的默认产能。铜丝规格、真实订单和期初实物由业务登记。

## 2. 数量、身份与版本

- 业务 ID 对外使用字符串，版本使用 JSON 非负整数。数据库数量 `DECIMAL(18,3)` 按吨记，金额 `DECIMAL(20,2)` 按人民币元记。接口用十进制字符串承载数量和金额，写入前校验范围和精度。均价等过程值保留所需精度。业务日按 `Asia/Shanghai`，实际发生日和录入时间分别留存。
- `p2_stock_balance.physical_quantity_ton` 由统一库存服务更新。有效预留按 `reserved_quantity_ton - consumed_quantity_ton - released_quantity_ton` 计算，可用量等于实物减有效预留。库存相关命令在修改实物或有效预留时都增加余额版本，便于发现评估或草稿之后的占用变化。已经验证存在余额行时保留原版本，首次合法写入可初始化余额行。
- `p2_supply_commitment` 的未兑现有效份额为承诺量减兑现量、减释放量。供料任务的累计有效承诺受对应物料、时间和可兑现产量约束。真实入库后，按实际可兑现量在同一生产事务更新承诺并建立或转换对应现货预留，未兑现部分继续单列。少产或延迟时标出受影响的用料任务。
- 车间一产出为通用 Φ8 铜杆。车间二同规格成品可先满足订单，再安排剩余部分。`manualPlannedRodTon` 是人工填写的剩余新加工范围用杆总量。后端按用料时点将现货及有效供料份额各扣一次，得到净新增杆量，再合并净新增量乘 `1.05` 并向上取至 `0.001` 吨，拆到任务日期时保持换算总量。
- 订单 `version` 表达订单编辑并发，`production_scope_version` 表达剩余加工范围的变化。影响该范围的数量、同规格归属和生产事实通过权威写入口更新范围版本。同一笔分配或产出被库存流水及归属关系引用时，按事实来源去重后计算剩余量。未知量、金额、交期之外的待补资料保留 `null` 及缺项记录。确认零量、零价、零金额应有明确事实。

## 3. 期初、到货与未来迁移

期初和铜板到货都使用原始 `movement_id` 作为公开记录 ID，对应 `OPENING` 或 `PLATE_RECEIPT` 流水。V4 按物料限制一条原始 `OPENING`。铜板当前只登记数量，Φ8 铜杆和确有实物的期初铜丝可另记原始总成本。期初未登记、确认无货、已有数量但成本待补分别展示。未登记的铜板或铜杆查询按缺项处理，成品按需求基线默认无货。

现有 V4 流水可存期初数量、日期、操作人和版本，缺少独立的原始总成本字段。V6 成本流水依赖核算批次。拟在期初能力落地时新增一份按合并时最新版本顺延的迁移，为 `p2_stock_movement` 增加可空的 `opening_total_cost_yuan DECIMAL(20,2)`。该列用于 `OPENING` 原始行及以其为根的更正行，保存当次确认的总额。服务校验铜板该列为空、适用金额非负，允许有库存但金额待补。已有历史由原依据补录，字段默认 `NULL`。V6 在真实成本服务可用后以同一原始流水为来源形成可追溯的核算记录。

更正继续引用原始流水的 ID，即使原记录已经更正过。每次追加 `CORRECTION` 数量差额并更新根记录版本，查询从原始行和最新有效更正投影出当前值。只补金额时差额为零，日期更正保存新业务日及原日期依据。数量更正同时检查相关日期后的领用、当下实物和有效预留，按影响范围返回下游冲突。原始值和每次更正留有审计。正式确认计划与分配可保留待核算状态，生产资料齐全后按来源触发补算并关联前后版本。

## 4. 评估、快照与一次确认

模块默认打开订单列表。新建和编辑只保存订单及相关审计。单选或多选订单后，用户明确发起 S2-P01 评估，两种操作共用接口。评估产出建议或待调整的同一类草稿，供后续人工编排。草稿保存在客户端，关闭只丢弃本次编辑。

| 对象 | 快照和版本安排 |
| --- | --- |
| 人工用杆总需求 | 在保存订单的人工用杆量或确认方案时，通过 `p2_customer_order.rod_demand_scope` 存储采用的订单、规格、剩余加工量及成品分配依据，并保存 `production_scope_version`。范围变了须核对人工总需求。 |
| 生效方案 | 在 `p2_plan.demand_snapshot` 保存一份不可被后续订单修改覆盖的确认依据，包括选中订单、人工总用杆、现货份额、有效供料份额、净补产量、备料量及其计算依据、覆盖日期和所采用版本。任务、预留、供料承诺以关系行作为后续执行依据。 |
| 并发条件 | `expectedVersions` 明确订单与加工范围版本、被替换方案和任务、库存余额、普通产能及涉及的特殊日产能。特殊日产能项记录 `workshopId`、`date`、`version`。仅预期尚无记录时版本为 `null`，已撤销的历史行也使用其已有版本。供料任务、承诺及归属份额覆盖相应版本或其持锁后的聚合条件。 |
| 受保护实际 | 在计划确认时核查已有实际开始、投入、领用及称重。读取 V5 的相应记录及共享任务版本。不能替换的任务保持原目标和真实差额，尚未执行的剩余需求可另排。 |
| 重排追溯 | `previous_plan_id` 表达单一直接前版。一次重排影响多个旧方案时，在当前快照与对应审计中保留各原方案及任务 ID/版本，用 `p2_plan_task.superseded_by_plan_id` 追溯被替换任务。含仍有效任务的旧方案继续保有这些任务的生效关系。 |

确认时服务端重建整个受影响集合，含客户选中订单以外的共用任务、供料、预留与规划范围外依赖。验证日期、物料、日合格产能、顺位、现货与承诺，并按替换范围释放原有效份额后计算新的份额。逐个核对车间二任务计划用杆量与所关联需求份额合计，再按需求键验证车间二跨任务合计与对应人工用杆范围及重新编排的剩余量一致。车间一补产任务的供料份额独立按供需关联及可兑现产量校验。车间一先生产入库，同日供料须在车间二领用前满足实际入库条件。禁止供需循环、无法兑现的承诺和挪用其他需求预留。整单已有同规格成品时，确认只建立成品归属及预留。发现库存、产能、供料或版本冲突时保留原草稿并返回受影响对象，不写入部分结果。

部分排产沿用同一个确认事务。按订单锁读已有有效任务及实际产出后，计算本次可安排范围，只保存本次确认的任务、对应预留和供料承诺。剩余待安排量由订单需求、已交付量、成品归属和有效任务的待产份额计算。失败时本次提交整体回滚，既有任务继续按原方案执行。

## 5. 事务与锁顺序

业务命令以一个 MySQL 事务完成审计、请求结果和实际业务写入。所有会影响排产、库存或交付的服务使用同一组加锁约定。先读取请求拟涉及的根对象，再按下列顺序逐一锁定。在同类根内按数值 ID 升序，在同一车间的日期内按日期升序。取得根锁后锁读当前条件，验证依赖集合仍与预先收集的一致。若发现新增受影响根，回滚后重新收集或返回相应冲突。

1. 先占用 `p2_request_result` 的 `request_id`，避免重复请求同时进入业务校验。命令按稳定序列化计算摘要，包含操作、路由上的业务对象及请求内容。同号同内容在比对后重放已提交结果，同号不同内容返回幂等冲突。首次写入中的业务失败和请求占位一起回滚。
2. 锁涉及的 `p2_customer_order` 行。对订单修改、分配、交付以及推进任务执行，校验当前版本、剩余量和可替换范围。
3. 锁 `p2_workshop_capacity` 车间根行，再锁已存在的特殊日设置。所有改产能、创建或更新该车间任务的命令都先取此根锁，避免两个方案同时占用同一顺位或超额日产能。V4 的顺位唯一键在单方案内生效，确认必须检查车间当天全部仍生效任务。特殊日尚无行时也用同一根锁协调创建。
4. 锁 `p2_material` 根行，再锁或按需创建 `p2_stock_balance` 行。物料根锁保护首次登记、余额尚不存在、现货与预留的合计以及同规格的成品自由份额。每个共享库存写入口遵守同一顺序。
5. 顺序锁定方案、任务、库存预留、供料承诺、成品归属、交付主记录、交付明细、原始流水及生产事实。每类明细内按主键升序锁定，仅锁本命令涉及的对象。按锁读的现状校验版本、数量及真实记录保护条件。创建新方案或任务时为所有客户端临时键分配真实 ID，再保存依赖行。写审计及幂等响应后提交，各关联 ID 应能由成功响应追溯。

现有公共 `IdempotencyService` 提供结果重放和业务回滚，但其实现是在执行写入后才尝试插入结果。系统二的并发确认、领用和交付须使用先占请求行再校验版本的事务路径，可在共享服务中实现并验收同号并发和目标错配。V9 的版本审计列为 `INT`，业务聚合版本为 `BIGINT`。如业务实现要求审计版本全域一致，在首个相关写接口上线前以新的有版本迁移扩充审计列宽。

## 6. 写入归属及验收

| 操作 | 权威写入口及事务结果 |
| --- | --- |
| 方案生效、重排和随计划分配 | S2-P06。同一次提交保存任务、预留、承诺和适用的成品归属，成品分配内部复用与 S2-D02 相同的能力。 |
| 独立公共成品分配、更正、订单减量及取消 | S2-D02/D03、S2-O07/O08。变动限定在相关订单的有效份额。分配或释放更新归属和预留，退回公库的是原有成品及其原对应成本。 |
| 实际投料、产出及领杆交接 | 生产记录 S2-R07、R09、R10、R12。保存实际的事务调用统一库存服务完成实物增减、适用预留的核销和供料兑现。领杆按实际交出量扣库，接收的补录更新同一交接事实。 |
| 交付及交付更正 | S2-D06/D07。确认本单规格及可交量，保存一笔交付和其明细，同时写实物出库、核销预留和来源。更正保留原始值、差额流水和实际日，检查其他归属及后续事实。 |
| 生产结束、约定金额、统计和核算 | 生产结束走 S2-R16，约定金额走 S2-O09。库存成本留痕及订单估算由核算模块按原始事实更新。价格、计量或成本待补时返回缺项。 |

验收使用隔离的二期开发 MySQL。同号并发只生效一次。不同草稿争同一份现货或跨方案同一顺位只允许一方生效，失败时事务完整回滚。验证缺口与 1.05 取整不因拆天而重复，未兑现的承诺不计入现货，有真实投入的旧任务不被替换。验证期初补成本不改变实物，公共成品分配不增加实物，交付部分数量只核销一次。真实一期数据只读验收另核对表计和覆盖范围，现场缺失数据按缺项展示。
