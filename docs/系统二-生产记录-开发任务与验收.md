# 系统二 · 生产记录开发任务与验收

按[需求基线第 8、9 节](需求基线.md#8-实际生产每日称重与订单归属)和[生产、能源与成本接口清单](api/生产能源成本接口清单.md)开发和验收。本文件的数量、时间和订单均为测试输入。订单、物料、有效计划、库存与交付的联调数据沿用[订单与计划开发任务与验收](系统二-订单与计划-开发任务与验收.md)。

## 1. 开发顺序

| 任务 | 前端交付 | 后端交付与依赖 |
| --- | --- | --- |
| 1. 首页和详情 | 默认显示今天的车间一、车间二任务，提供历史查询与「计划外生产」入口。任务详情分为摘要、时间线、登记操作。摘要分列计划日和实际日、计划量、实际量、差额与待补项 | S2-R01/R02 读取已确认计划的同一 `taskId` 和实际投影。S2-R03/R04 查询历史实际及来源、关联、版本、更正和缺项。依赖 S2-P03、车间主数据与统一库存查询 |
| 2. 车间一计划内投料与称重 | 任务详情登记实际铜板重量和可待补的材料总额，按次录入实际 Φ8 铜杆称重。保存后回显原材料出处、每次称重、实际累计和缺项 | S2-R07/R09 复用订单与计划的库存与预留能力。投料、出库及应核销预留同一次保存。每次称重保存真实新增量、投入引用、入库及供料兑现关系。以前置手工方案 S2-P06 验收，无需等待自动排产 |
| 3. 实际起止和补录 | 在时间线登记实际时段、按实际日补录、打开历史记录及其更正。首次投料、交接或称重可以同时登记实际时段 | S2-R05/R06 处理执行记录。任务详情保留原计划目标，实际按业务日入账。按 V5 核对实际记录与归集关联，验证已有实际的任务受重排保护 |
| 4. 车间二交接与换单称重 | 录交出、接收或待补接收，超差展示放行条件。换单或日末停机后按刚结束的任务登记本次铜丝称重，展示订单归属及公共差额 | S2-R10/R11/R12 读取统一铜杆库存和有效供料，保存一次出库、核销对应预留。铜丝按规格一次入库，并同事务保存直接归属及对应成品预留。S2-D01/D04 回查归属与可交数量 |
| 5. 任务结束、订单结束和零产出 | 任务结束后可查待称重。零产出明确选择任务或车间整日。订单不足量结束展示原要求、合格量、差额、原因及后续可交数量 | S2-R14/R15/R16 区分零产出、无记录、任务停止及订单结束。对照 S2-O03/O09、D04/D06、P03，核对结束信息、交付、约定金额、有效任务及保留份额 |
| 6. 更正与并发 | 从原记录发起更正，填写原因，展示原值、新值、下游影响及冲突，保存后定位到新版本和变更记录 | S2-R06/R08/R11/R13 校验原版本，同事务修正有效值、库存差额、归属、预留及适用下游依据。金额补录、接收补录、时间修正分别复用原事实。关键写入统一幂等及锁顺序 |
| 7. 计划外实际 | 入口填写车间、实际日、产品、补录原因和经办人，并提交第一笔实际。在同一归集组继续补录，历史及详情标记「计划外生产」 | 拟增 S2-R17 `POST /api/v1/production/unplanned-records`。首笔成功创建实际归集组，后续携同组 ID 及整数版本。复用已验收的投料、交接、称重、归属和更正规则。R14 继续使用任务或车间整日确认。依赖 V5 后续增量迁移及 R03/R04 实际投影 |
| 8. 当日录全确认 | 按车间、实际日展示当前已录事实、待补项及「当日录全」状态。明确确认后可查时间、经办、确认依据及后续失效提示 | S2-R18 `GET /api/v1/production/workshops/{workshopId}/days/{actualDate}/record-status`、R19 `POST /api/v1/production/workshops/{workshopId}/days/{actualDate}/record-completions`。命令校验 `expectedVersion` 和 `expectedSourceRevision`，事实变更同事务使受影响日确认失效。依赖增量迁移及实际更正联动 |
| 9. 交付与核算联调 | 生产详情显示库存、订单和记录链接。数量已保存时显示真实缺项及待核算。按关联 ID 查费用依据 | S2-R 原始事实、版本及当日录全依据由 S2-E、S2-K 读取。复用成本账和补算接口。已有 V5 数据迁移、跨日、下游更正和并发用真实开发 MySQL 验证 |

任务 1 的页面和任务 2 的库存事务可以并行开发，共用任务摘要及保存结果契约。首轮验收任务 1 和任务 2 的任务查询、铜板投料与铜杆两次称重。继续联调前，确认 S2-P03、S2-R02 与库存流水使用同一个任务 ID。完整核算引擎接入后使用已经保存的材料金额、归集关系与称重事实做补算。

## 2. 首轮验收数据及步骤

使用隔离的二期开发 MySQL。以实际业务时区的日期 D 和 D+1 为测试日期，创建计划时保持日期可排，登记实际时使用已发生的日期或可控测试时钟。参考数据接口返回车间 ID，S2-I01 返回物料 ID。不同场景使用独立夹具或还原初始快照。

| 步骤 | 输入与应验结果 |
| --- | --- |
| 1. 建立期初和有效计划 | 铜板现货 20.000 吨，Φ8 铜杆现货 4.000 吨，成品为零。用 S2-P06 确认 D 日车间一产杆 6.000 吨、D+1 日车间二为订单 A 产丝 8.000 吨。铜板预留 6.300 吨，车间二有 4.000 吨杆现货预留及 6.000 吨未来供料承诺 |
| 2. 首页、详情及待统计 | 在 D 日打开「生产记录」，默认展示两个车间及各自今日任务。车间一的任务 ID 与 S2-P03 相同。切至 D+1 能查车间二任务。车间一详情显示计划 6.000 吨，实际量为空且待统计。摘要、时间线、登记操作均可打开 |
| 3. 实际铜板投料 | 在车间一任务使用 S2-R07 登记实际投入 6.300 吨，材料总金额填 360000.00 元，记真实日期。成功后铜板实物 13.700 吨，关联预留清零。只有一笔 6.300 吨出库，响应及详情能追到投料和流水 ID |
| 4. 分两次实际称重 | 对该投入依次使用 S2-R09 登记 Φ8 铜杆 2.000 吨和 4.000 吨。第一笔后任务实际累计 2.000、差额 4.000，第二笔后累计 6.000、差额 0.000 吨。杆实物余额先到 6.000、再到 10.000 吨。形成两笔入库和累计 6.000 吨供料兑现，投料记录与材料金额单一来源 |
| 5. 核对计划与生产派生信息 | S2-P03 保留车间一计划 6.000 吨，历史能按实际生产日找到两次称重。S2-I12 可逐笔核对一次出库及两次入库。S2-I14 可核对承诺和兑现。订单只在合格铜丝称重形成归属后增加已产铜丝量 |

同一夹具另跑材料总额留空。实际投料和称重照常保存，成本状态及缺项可追到原投料。以后 S2-R08 仅补材料金额，铜板实物、预留及已有数量流水保持。该场景与成功重试、事务中途失败一并签收。

## 4. 时间、缺项和范围验收

| 场景 | 应验结果 |
| --- | --- |
| 计划日 D，实际 D+1，D+2 补录 | 实际按 D+1 计，录入时间另存为 D+2。历史按实际日查，原任务仍以 D 日显示于计划中，计划量和实际量各有来源。已有对应任务时使用原任务登记 |
| 只有实际停止时段且尚未称重，另一个任务同日曾正常称重 | R05/R15 的停止事实可见，未称重任务实际量为空并显示待统计。日汇总返回已知产量及缺项。补齐后实际按原业务日更新 |
| 车间某日两个任务，A 经 R14 确认零合格，B 未称重 | A 实际量显示已确认 0.000，B 待统计，整车间当日范围保留缺项。不生成实际入库，不认定整日已确认零 |
| 无正产量且经办能确认同一车间整日确无合格产出，R14 提交车间整日范围及原因 | 整日为已确认 0.000，按车间与日期追溯范围及原因。设有一笔正产量的独立场景，整日零确认被拒绝，原称重有效。若发现整日零确认误录，通过 R13 携原版本及原因作废，再按实际日期补称重。查原零记录和更正历史可追溯，作废本身无库存流水 |
| 车间 D 日尚无录全确认，读取 R18，再完成实际称重并重新读取 | 未建状态行时 `version`、`sourceRevision` 为整数 0，`recordsComplete=false`，`confirmedSourceRevision=null`。事实保存后读取最新状态，已知量、`blockingItems` 和来源修订号可对应到同一车间与实际日 |
| 当日已发生的投入、交接、称重等事实已登记，经办执行 R19 | 携 `requestId`、`operatorName`、`expectedVersion`、`expectedSourceRevision` 保存。成功后 `recordsComplete=true`，新版本和 `confirmedSourceRevision` 可查。仅某一任务 R15 完成时，车间整日仍按其独立状态展示 |
| 材料总额、能源或价格尚缺，或者交接记录处于待接收，已发生的事实已登记 | 这些缺项单独存在时，R19 可以确认事实录全，原始空字段、待接收状态和成本待核算继续可查。另以已知已停但缺称重/停止记录、或零产出冲突的场景提交，`blockingItems` 明确指出需要核实的实际事实 |
| 全车间无合格产出，仅空称重列表就尝试 R19 | 返回对应缺项。先通过 R14 确认车间整日零产出并核实其余事实后，才按当前状态和来源修订号确认录全。零产出证据与录全依据分别可追溯 |
| D 日和 D+1 日均已录全，之后补录 D 日产出，或将 D 日事实更正到 D+1 | 补录使 D 日录全失效。跨日更正使原 D 日、新 D+1 日的确认均失效。历史确认仍可查，当前状态待重新确认，统计更新已知量且保留待核算提示 |
| 车间二实际 7.000 吨，仍有未安排或部分已安排的订单需求 | 订单实际由合格称重归属更新，已安排、待安排和实际分别可查。实际变化提示受影响计划，未来任务与相应计划预留通过 S2-P06 确认调整 |

## 5. 计划外及数据升级验收

| 场景 | 复现与应验结果 |
| --- | --- |
| 车间一没有适用已确认任务，铜板现货 20.000 吨，Φ8 杆库存 0.000 吨 | 用 R17 首次保存实际铜板投入 3.150 吨，携真实业务日、车间、产品、经办与补录原因。返回归集组、事实 ID、版本和唯一出库。持该归集组 ID 及最新版本登记两次实测产杆 1.000、2.000 吨。铜板余额 16.850 吨，杆实物 3.000 吨，两次称重与投料在一个组中可查 |
| 车间二找不到对应任务，已发生领杆交接并产出，订单 A 规格与铜丝相符且尚需 2.000 吨 | 首次在 R17 登记交出和接收各 3.000 吨，补记同组称重 2.400 吨，A 归属 2.000 吨，公共 0.400 吨。出库 3.000 和入库 2.400 吨各一次，产生 A 成品归属及对应交付预留。实际业务日统计 2.400 吨，R03/R04 标记来源并保留补录原因 |
| 核对计划侧和实际侧 | 对比 R17 前后的 S2-P03、P04、计划预留、供料承诺与日产能占用，保持同一批已确认对象。计划外实物变化和订单直接成品归属可从各自库存流水查询。订单待安排量按最新实际归属刷新，可能受影响的已生效任务显示提示 |
| 重复首笔、续填与组版本冲突 | 同一请求重放得到同一归集组和事实。续填使用已有组和版本，旧版本提交显示冲突并保留表单。首次保存的库存过账失败时，归集组及事实均未生效。实际日不同于计划日且对应任务明确的计划内记录仍沿原任务 |
| 拒绝不一致的补录 | 使用不相符的物料规格或归集组版本、试图侵占其他订单预留、提交未发生的实际日期。显示对应的字段或状态问题，计划、实物及实际记录保持一致。既有实际时间线继续可查 |
| 升级已有开发数据库 | 对既有 V5 数据快照应用生产记录的增量迁移，再从计划详情及历史实际回查原 ID、任务、重量、业务日和库存流水。在同一数据库中新建合法计划外记录。用空库执行完整迁移核对相同接口。旧数据缺材料金额的状态为待补 |

## 6. 异常、并发和签收

| 复现方法 | 应验结果 |
| --- | --- |
| 两个独立数据库连接读取相同库存版本，各试图领用 10.000 吨现货中的 6.000 吨 | 仅一笔成功，最终实物 4.000 吨。另一笔返回适用的库存、版本或状态冲突，无额外交接、出库或成本依据 |
| 两个写请求使用同一旧订单版本，对同一剩余需求同时申请直接归属 | 一个请求提交成功后另一个返回版本冲突，保留后者表单。更新依据后可另行提交真实称重，响应明确给出最终归属及公共差额。归属合计不超剩余需求，同笔成功称重只入库一次 |
| 同一车间同一业务日，整日零确认和正产出并发提交 | 至多一方生效。若称重先保存，零确认返回冲突。若零确认先保存，补称重返回冲突，核实后可先作废误录零确认 |
| 两会话读取同车间同日相同状态，再提交 R19，或在 R19 期间保存新实际 | 两次 R19 校验同一版本，至多一个成功。若新实际先保存，旧来源修订号的 R19 返回冲突。若 R19 先成功，新实际保存后立即使该日确认失效。最终录全状态与已保存事实修订一致 |
| 相同 `requestId`、相同操作及内容并发或超时重试，再以相同 ID 更换内容 | 原成功结果可重放，任务/归集 ID、实际 ID、出入库与预留结果一致。更换内容返回 `IDEMPOTENCY_CONFLICT`，数量和版本没有额外变化 |
