# 系统二 · 订单与计划需求对齐稿

状态为业务对齐记录。用户已确认默认进入订单列表，以及保存订单后主动发起单单或多单评估。具体页面规格和实现约束见[开发文档入口](系统二-订单与计划-开发指南.md)。

## 1. 模块范围

「订单与计划」负责客户订单、物料与库存、产能维护、方案评估与编排、已生效日计划、成品分配和实际交付。实际投料、领用交接、称重和生产结束由「生产记录」登记。订单核算读取同一份实际、库存及交付依据，在「生产与能源统计」展示。

业务规则以[需求基线](需求基线.md)第 3–7、9 节为准。接口从[订单、库存、排产与交付接口清单](api/订单库存排产接口清单.md)细化。生产、能源与成本的衔接查[生产、能源与成本接口清单](api/生产能源成本接口清单.md)。历史对话中已归入需求基线的决定继续适用。

## 2. 一张订单如何走完

| 步骤 | 用户操作与系统结果 |
| --- | --- |
| 建单 | 填写订单编号、客户、铜丝规格、需求吨数和交期。一单一种规格。录入合同总金额，暂缺时标为待补。保存订单后得到可查询的订单。 |
| 评估 | 对选定的一张或多张订单先评估一次。按规格检查可用成品，再按剩余加工范围检查用杆依据、可用铜杆现货、可兑现的未来供料、铜板、两车间产能和交期。 |
| 编排 | 成品足够时进入成品分配草稿。需要生产时，可安排的方案带入系统建议，需要调整时由人在同一个草稿里填写或修改加工日期、任务次序、数量和供料安排。 |
| 确认 | 用户确认一次。服务端在同一事务校验最新版本、库存、产能和供料。成功后计划、对应预留和适用的成品分配同时生效。 |
| 执行 | 「生产记录」读取已生效任务，实际登记过账后更新库存、任务进展及订单产量。 |
| 交付 | 按本单已分配的真实合格成品判断可交付，实际交付另行登记，按实际量扣实物及对应预留。生产、交付、核算分别显示。 |

草稿及评估不占库存或正式产能。保存冲突在原草稿中处理，退出未保存的草稿时原有效安排及预留继续生效。

## 3. 开发时必须使用同一口径

- **成品先匹配。** 成品完全满足时只确认成品分配和预留。部分满足时，用杆总需求由用户针对剩余新加工范围填写或重核。用杆依据缺失时可以保存订单，涉及新生产的方案需补齐后才能确认。
- **总需求与净补产分开。** 人工填写的是计划用杆总需求。系统按用料时点扣除本次可用现货及有效未来供料一次。净新增铜杆合并后乘 1.05，向上取整至 0.001 吨，按日拆分不再重复计算。
- **现货、预留与预期供料分开。** 预留减少可用量，实际领用或交付才扣实物。未来铜杆按供料任务和用料任务关联，实际称重入库后方可领用。同日衔接明确先入库后领用。
- **按天、按车间校验产能。** 两车间普通日产能初始各 10 吨，可分别调整。特殊日期覆盖普通值，零表示停产。同日可有多个顺序任务。车间二以交期为依据倒排，车间一统筹未来未开始的净补产需求。联合重排需展示影响、保护已开始或已有实际的任务。
- **库存与成本边界。** 铜板到货按实际重量入库。投料材料总金额在登记实际投入时录入。期初铜杆录入吨数及总成本，已有吨数可在成本待补时保存。铜板短缺时提示采购或协调，完整采购通过独立流程处理。
- **订单变化留痕。** 改期、优先级、增减量、取消及更正保留历史和影响。涉及共用供料时保护其他订单的有效份额。不足量结束保留原需求、实际和差额，已完成部分仍可交付。

## 4. 已确认的页面操作

| 决定 | 操作约定 |
| --- | --- |
| 模块首页 | 默认进入订单列表。在「订单与计划」内部进入库存、产能和日计划，不增加侧栏入口。交付记录从订单详情进入。 |
| 建单后何时评估 | 「保存订单」单独保存。单张订单从详情发起「评估排产」，多张订单从列表勾选后发起「联合评估」。 |
| 急单优先 | 用户可将订单标为优先，允许它跨交期先参与联合排产。订单仍按原交期提示风险，列表默认按交期展示。 |
| 延期方案确认 | 方案预计晚于原交期时，草稿先显示延期提醒。用户点击同一个「确认保存」接受调整，库存、产能和供料校验通过后方案生效。订单原交期保留，继续显示延期风险。 |
| 部分排产确认 | 草稿展示本次安排量及剩余待安排量。用户可先确认满足库存、产能和供料要求的任务，其余需求留待后续安排。订单原需求和交期保留。后续排产计入已有有效任务，实际合格产量按称重记录更新。 |

缺料、缺产能和缺用杆量的具体交互按[页面与交互规格](系统二-订单与计划-页面与交互规格.md)落实。草稿保留问题明细及原编辑内容，用户补齐事实后在原草稿校验。

## 5. 第一轮走查场景

1. **成品足够。** 订单需求 10 吨，同规格可用成品 10 吨。评估带入成品分配草稿。一次确认后出现本单预留和交付条件，车间无需生产。
2. **现货与补产。** 订单有剩余加工需求，确认计划用杆总量为 10 吨，可用铜杆 4 吨，且无其他有效供料。草稿分别列出现货 4 吨、净新增铜杆 6 吨和铜板需求 6.300 吨。确认后仍只有 4 吨现货，6 吨对应未来供料任务。
3. **同一库存发生竞争。** 两份草稿均拟使用同一份现货。第一份确认成功，第二份显示具体冲突并保留编辑内容，库存不得重复承诺。
4. **部分排产。** 订单需求 10 吨，目前有条件安排 6 吨。一次确认后这 6 吨的任务及对应预留生效，另有 4 吨待安排。后续在保留已有任务时，只安排剩余 4 吨。

## 6. 最终开发文档的交付内容

1. **业务与状态**。范围、角色和操作路径、每步前置条件、状态变化、跨模块责任与异常处理。
2. **页面**。页面入口和导航、字段与单位、按钮生效条件、空态和缺项、重排和冲突处理。
3. **接口**。每个操作对应的接口、完整请求和响应示例、字段约束、错误码以及前端处理方式。
4. **数据与事务**。对照现有 V4–V6 迁移列出表和字段、计算规则、事务与并发、幂等与审计，标明设计缺口及必要的后续迁移。
5. **任务与验收**。按依赖顺序拆任务，给出联调步骤、验收输入和可核验的预期结果。先跑通订单、库存、人工日计划一次确认及实际入库，再接自动评估和联合排产。
