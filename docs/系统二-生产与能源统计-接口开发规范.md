# 系统二 · 生产与能源统计接口开发规范

本文用于前后端开发及联调，依据[需求基线](需求基线.md)第 10–11 节及[生产、能源与成本接口清单](api/生产能源成本接口清单.md)的 S2-E01–E06、S2-K01–K06。请求格式、数字精度、幂等和错误信封沿用[接口通用约定](api/接口通用约定.md)。订单状态和原始事实分别复用[订单与计划接口开发规范](系统二-订单与计划-接口开发规范.md)及[生产记录接口开发规范](系统二-生产记录-接口开发规范.md)。本文是开发契约，字段名及默认值为研发约定。

## 1. 入口和调用顺序

默认首页查询当天两个车间的总量概览。模块内部四个主要视图为总量统计、订单核算、库存成本、能源价格。每日分摊从总量记录展开，核算运行从消息或结果详情进入。实际输入或金额缺项可跳到源记录补齐，再查看其自动触发的核算进度。价格维护用 S2-E05/E06，受控补算用 S2-K05。

| 用户动作 | 对应接口 |
| --- | --- |
| 查看两个车间的日期总量 | S2-E01 显示两个独立车间，每个车间分别列电、水、煤气和本车间合格产量。 |
| 展开一项消耗 | S2-E02 按实际日、车间和能源类型查询来源、计量范围、质量及刷新依据。 |
| 查看车间一天的成本分摊 | S2-E03 查询该日总耗、实际称重分母、订单与公共份额、适用价格及版本。 |
| 查看单价及其生效依据 | S2-E04 查询指定能源、范围和日期。首次新增用 S2-E05，原始误录的留痕更正用 S2-E06。 |
| 查看某订单成本及盈亏 | S2-K03 查询列表，S2-K04 展开来源和缺项，并提供原订单、生产事实、交付及原始价格链接。 |
| 查看在库价值和成本流转 | S2-K01 查询库存成本，S2-K02 追溯数量源事实和成本流水。 |
| 补齐来源后补算或重试失败运行 | S2-K05 发起并返回运行 ID，S2-K06 轮询结果。已由源命令触发运行时直接查询其返回 ID。 |

所有查询使用明确的实际日期范围。首页将当天作为 `from` 和 `to`，允许切换日期或区间。价格适用、生产统计和补算范围都按实际日取值。录入时间与源刷新时间分别展示。

## 2. 十二项接口映射

以下相对路径均以 `/api/v1` 为前缀，保留原清单编号与方法。集合分页返回 `items/page/pageSize/total`，默认 20 条，最大 100 条，页码从 1 开始。

| ID | 方法与相对路径 | 请求字段 | 响应的 `data` |
| --- | --- | --- | --- |
| S2-E01 | `GET /energy/totals` | `from,to,workshopId?` | `from,to,workshops[]`，每个车间内的四项总量及完整性、来源摘要、缺项。省略车间查询两个实际生产车间，ID 从共享字典读取。 |
| S2-E02 | `GET /energy/daily-consumptions` | `from,to,workshopId?,energyType?,qualityStatus?,completeness?,page,pageSize` | 按实际日、车间、能源、来源身份稳定排序的分页日来源记录及缺口记录。 |
| S2-E03 | `GET /energy/workshops/{workshopId}/days/{actualDate}/allocations` | 路径车间和日期，可选 `costRunId` | 当天来源、产量、价格与已发布分摊快照，或者待核算依据和缺项。指定运行时只读该运行快照。 |
| S2-E04 | `GET /energy/prices` | `energyType?,workshopId?,scope?,effectiveFrom?,effectiveTo?,actualDate?,includeHistory?,page,pageSize` | 价格分页。指定车间、能源和实际日时附 `matchedPrice` 及匹配依据，范围取 `GENERAL` 或 `WORKSHOP`。 |
| S2-E05 | `POST /energy/prices` | `requestId,energyType,workshopId,effectiveDate,unitCode,unitPriceYuanPerUnit,operatorName` | 新价格 ID/版本、适用范围、受影响的缺价结果及适用 `costRunId`。 |
| S2-E06 | `POST /energy/prices/{priceId}/corrections` | `requestId,expectedVersion,changes,reason,operatorName` | 原新价格 ID、版本、变更记录、受影响范围及适用补算运行。 |
| S2-K01 | `GET /costing/stocks` | `materialId?,materialType?,specification?,costRunId?,page,pageSize` | 同一核算快照的实物、预留、自由公共份额、在库价值和均价口径，单列当前数量、完整性、缺项与版本。 |
| S2-K02 | `GET /costing/stock-ledger` | `materialId?,orderId?,from?,to?,sourceType?,sourceId?,costRunId?,page,pageSize` | 成本流转分页，含 `entryType`、数量依据、均价、金额差量、源事实和原更正关联。 |
| S2-K03 | `GET /costing/orders` | `orderId?,wireMaterialId?,productionResult?,accountingState?,page,pageSize` | 订单编号、状态轴、适用金额及确认、已知成本、完整总成本、盈亏与可展示条件、缺项和核算版本。 |
| S2-K04 | `GET /costing/orders/{orderId}` | 路径订单，可选 `costRunId` | 订单核算详情、各有效成本项、仅供追溯的上游组成、金额来源及版本、快照和历史关联。 |
| S2-K05 | `POST /costing/recalculations` | `requestId,sourceReferences,requestedScope,expectedVersions,expectedSourceRevision,expectedPublishedCostRunId,reason,operatorName`，失败重试可带 `retryOfCostRunId` | 实际影响范围、运行 ID、状态与缺项。范围由服务端追溯确认。 |
| S2-K06 | `GET /costing/runs/{costRunId}` | 路径运行 ID | 状态、运行版本、前一运行、来源快照、已发布结果关联、缺项、安全错误及可重试条件。 |

S2-E01 的 `workshops` 是已知两个生产车间的小型集合。S2-E02 覆盖整个请求范围内的能源日槽，存在缺表计或缺记录时仍返回可定位的缺口项。分页切换仅影响列表，不改变总量汇总。

## 3. 统一字段和判定

### 3.1 完整性、单位及源读取

| 字段或值 | 含义 |
| --- | --- |
| `completeness=COMPLETE` | 请求范围的对应来源覆盖已确认，计量或实际记录可用，结果为完整数值，可包含明确的零。 |
| `completeness=PARTIAL` | 已有一部分合格来源，但完整范围、质量、称重或归属仍有缺项。`knownValue` 表示可追溯已知部分，`value` 为 `null`。 |
| `completeness=MISSING` | 没有可采纳的对应来源。`value`、`knownValue` 为 `null`，返回具体缺项。坏质量或 `NO_DATA` 槽按缺项表达，保留原质量和值供追溯。 |
| `knownCostAmountYuan` | 已有充分依据部分的成本。没有可核算项为 `null`，已有明确零项才为 `"0.00"`。 |
| `totalCostAmountYuan` | 必要成本齐全时的完整总额，缺任何必要组成时为 `null`。 |
| `missingItems[]` | `code,sourceType,sourceId,workshopId,actualDate,field,message` 中适用的字段。每条定位可补齐的原始依据。 |
| `sourceSnapshot` | 来源类型、主键、范围、数量、单位、质量、刷新时刻、采纳规则和指纹。核算运行保存其输入时点的完整副本。 |

电、水、煤气分别使用 `ELECTRICITY`、`WATER`、`GAS`，单位为 `kWh`、`m³`、`Nm³`。适配一期 `COAL_GAS` 编码时统一映射为 `GAS`。每类能源单独计量及计价，价格对应元/该单位。重量吨数为最多三位小数的字符串，金额总额为最多两位小数的字符串。消耗、单价、均价和比例保留其所需精度。

E01 产量来自二期有效合格称重及明确零产出事实。未称重或同日部分记录未齐时保留已知量和缺项。车间一、车间二的产量分别返回。计量来源先核对表计身份、车间范围、能源种类和有效覆盖，不叠加设备分表与总表。符合范围的 `GOOD` 日数据优先。日数据不存在时，可用完整 24 个 `GOOD` 小时数据回补同日，并保存所用小时集合。已有 `PARTIAL/BAD/NO_DATA` 日记录时按对应质量与覆盖返回缺项，保持可追溯。日与小时的同一消费范围采用单一口径。具体来源采纳规则见[数据与计算设计](系统二-生产与能源统计-数据与计算设计.md)。

一期日表的一行 `GOOD` 不独立证明车间计量范围完整。源适配层将质量、范围、时间覆盖和可采纳条件一起返回。区间有两天完整、一天缺失时，`knownValue` 汇总两天已知部分，`value=null`，完整性为 `PARTIAL`。确实计量为零且来源完整时返回 `value="0"` 和 `COMPLETE`。缺表计时两项值均为 `null`。

### 3.2 价格匹配和更正

统一价格服务先选择该车间专用范围，专用范围中存在生效日不晚于实际日的有效记录时，取最新一条。专用范围无适用记录时回退通用范围并取最新的适用记录。查询和结果均返回匹配范围、价格 ID、版本、生效日和单价。`workshopId=null` 表示通用范围，具体 ID 表示专用范围。单价可为明确零，禁止负数。物料或车间 ID 使用真实来源身份。

同能源、同范围、同生效日只有一条当前有效价。正常新增一条未来生效价仅从其生效日覆盖后续价格匹配。补齐原来没有适用价的日期可触发缺价结果补算。已采纳的车间日能源价格随已发布快照固定，同一运行其他项仍为 `INCOMPLETE` 时也保留已经采纳的正常价格。源价格原始误录走 E06，明确改后值和原因，保留原价格及 `supersedesPriceId` 链，识别受影响的历史与后续成本引用再补算。

E06 的 `changes` 可包含 `unitPriceYuanPerUnit`、`effectiveDate`、`unitCode`、`energyType`、`workshopId`，省略字段保留原值，`workshopId=null` 明确更正为通用范围。单位必须与更正后的能源相符。实际能源身份或通用/车间范围变更须重新校验新有效唯一键，并追溯原新两侧所有受影响的实际日、匹配与已采纳引用；先前价格行及其旧范围保留历史。不能用后来的普通价格替换先前已核定依据。所有价格按真实用能日选择，不随订单日期、补录日期或查询当天改变。

### 3.3 日期分摊、均价与利润

车间二一天实际合格产量已完整时，以各订单当日实际归属合格量除以当日全部合格产量作为分摊权重，公共成品进入分母并保留对应费用。能源全日消耗包含待机空闲。明确全天无合格产出时，费用单列车间 `NO_OUTPUT`。待称重及分母不完整时暂不分摊，返回 `PENDING` 目标及缺项。正产量日通过生产记录 S2-R18 读取日状态、S2-R19 确认当天记录已录全，得到与当前日源修订一致的证据。之后补录或更正使证据失效，统计重回待核算。相关调用见第 7 节。

车间一同一次同日生产的实际材料总金额按各次合格铜杆重量拆分，投入金额按 `inputId` 去重。当日车间一能源按该日全部合格铜杆重量分配，再归入对应铜杆入库成本。金额尾差按统一规则守恒，后续称重补录触发重算。跨日尚未产出及全天仅待机的两类场景按基线 11.12 保持待核算。

铜杆均价以全部在库实物及对应成本计算，预留不扣在库量或价值。公共铜丝均价按仍自由的同规格公共量及成本计算，已归属订单的成本单列。订单有效成本项为 `ROD_ISSUE`、`PUBLIC_FINISHED`、`WORKSHOP_ENERGY`，按来源份额避免重计。原投料和车间一能源作为上游追溯依据，在已包含它们的铜杆带入成本中保持同一份额。

铜丝产出的上游成本按原称重的有效 `rodUseReferences[{handoverId,sentQuantityTon}]` 追溯实际交出成本份额。只有唯一明确来源时后端可推导。多次或跨日称重且用杆来源未齐时，保存原产量并返回 `ROD_OUTPUT_LINK_MISSING`，有关公共份额和订单成本待核算。补正后按原交接成本及引用份额重算，累计引用不超过交出量。K04 展示对应关系并链接生产记录，成本查询和补算不新增领料数量。

K02 的 `quantityBasisTon` 为非负依据量，`costDeltaYuan` 是库存价值的有符号差量。期初、入库增加价值，领用和交付减少价值，`ASSIGN/RELEASE` 以公共与订单两个份额记录，带相反符号并合计为零。订单有效 `ROD_ISSUE/PUBLIC_FINISHED` 成本项以正数表达承担金额。交付结转库存价值沿原订单成本份额追溯，订单成本不再增加同一笔费用。补算结果可用有符号更正差量及历史关联表达，页面总额从当前有效结果读取。

| 订单条件 | `estimatedProfitYuan` 与展示 |
| --- | --- |
| 正常新生产结束、金额明确且成本齐全 | 按有效金额减完整成本返回估算盈亏，`profitDisplayable=true`。 |
| 完全由已确认成品满足，金额与成本齐全 | 沿 `productionResult=NOT_REQUIRED` 核算，`profitDisplayable=true`。 |
| 不足量结束且实际约定金额确认、成本齐全 | 使用实际约定金额，保留原要求、实测量和差额，可展示估算盈亏。 |
| 减量后新金额尚未确认 | 展示当前数量、旧合同金额及有效成本，盈亏 `null`，标记待确认金额。 |
| 生产中、金额或必要成本缺失 | 盈亏 `null`，返回已知成本及缺项，`accountingState=PENDING`。 |
| 取消订单 | 盈亏 `null`、`profitDisplayable=false`，`accountingState=NOT_APPLICABLE`，历史成本及转公共的份额继续可查。 |

`accountingState` 沿用 `PENDING/COMPLETE/NOT_APPLICABLE`，生产与交付状态仍分列。`costCompleteness` 表达成本部分是否完整，运行 `status` 表达一次核算任务的执行状态，三个字段分别判定。材料与能源简化估算范围随响应返回 `costBasis=MATERIAL_AND_ENERGY`。

## 5. 受控补算、发布和轮询

### 5.1 命令及来源快照

S2-R08/R11/R13、S2-E06 等源更正命令保存成功后自动识别成本影响，同请求可同步完成或返回运行 ID。S2-K05 用于明确来源补齐后的受控补算及失败重试。页面从 K06 取得所需来源标识及版本，传回引用而不提交自行修改的库存、均价、金额结果或利润。

`POST /api/v1/costing/recalculations`

```json
  "requestedScope": {"workshopIds": ["2"], "from": "2027-01-01", "to": "2027-01-31", "orderIds": ["9001"]},
  "expectedVersions": {
    "orders": [{"id": "9001", "version": 3}],
    "costRuns": [{"id": "9101", "version": 2}]
  },
  "reason": "原价更正触发的自动运行失败后重试",
  "operatorName": "张工"
}
```

```json
{

  "message": "成功",

    "costRunId": "9105",
```

上例假定原自动运行 `9102` 已失败，服务端依据当前来源受理新重试。服务端根据来源关系返回实际完整影响范围，上例包含未由客户端列出的 `9002`。运行开始时读取相关原始事实、计量、价格、归属、成本状态及版本，保存可重现的输入快照。来源指纹按实际内容、范围、质量和刷新标识生成。核算服务的 `sourceRevision` 代表采纳的核算来源修订，`publishedCostRunId` 是当前发布基线。运行记录这两项，发布时按源修订和当前指针做条件更新。异步计算期间来源变化时保留历史运行，并返回可核对的失败或重试依据。源内容和实际业务关系追溯完整后，可全历史重放，或按受影响及其后继库存事件重放，发布结果满足同样守恒和版本要求。

来源类型白名单包括 `PLATE_INPUT`、`ROD_HANDOVER`、`ROD_OUTPUT`、`WIRE_OUTPUT`、`OPENING_BALANCE`、`ENERGY_SOURCE`、`ENERGY_PRICE`、`FINISHED_ALLOCATION`、`DELIVERY`、`ORDER_AMOUNT`。有业务记录版本时使用整数 `version`。一期能源源没有二期整数版本，使用 `sourceKey` 与 `fingerprint`，其内容和格式由 E02/K06 返回。更正和重试只采纳允许变更的来源，已核定历史引用的其他正常价格继续沿原快照。

其中正产量日完整性作为 `PRODUCTION_DAY` 来源快照保存，包含车间、实际日、日状态版本和 `confirmedSourceRevision`。核算全局 `sourceRevision` 与生产记录中的车间日 `sourceRevision` 分属各自范围，响应对象明确其作用域。

### 5.2 运行状态

| `status` | 页面与后续动作 |
| --- | --- |
| `PENDING` | 已受理，等待执行。页面按运行 ID 查询。 |
| `RUNNING` | 正在读取来源、计算和准备发布。显示影响范围。 |
| `INCOMPLETE` | 已完成当前可计算部分，仍有缺项。可原子发布新一版已知部分与明确的空值，替换当前有效结果指针。显示已知部分与补齐入口，补齐后由来源命令触发或用 K05 提交新运行。 |
| `COMPLETED` | 该运行影响范围处理完成并原子发布。订单是否可展示盈亏仍依其生产、金额和成本条件。 |
| `FAILED` | 本次计算或发布失败，保留上一有效结果指针和历史值。当前来源已经变化时，当前查询仍按待核算返回，旧金额放入 `previousResult`。提供安全原因及 `retryable`。 |

轮询通过 `GET /api/v1/costing/runs/9105`。页面以三秒间隔查询 `PENDING/RUNNING`，离开运行详情或进入终态后停止，手动刷新仍可查看。一次请求失败保留运行 ID，网络恢复后继续读取。K05 原样重试返回原运行，失败运行确需新执行时填写 `retryOfCostRunId`，使用新 `requestId` 并重新核对当前来源。服务端识别同一来源快照已有待执行或执行中的运行时可复用该运行，并返回其 ID。

## 6. 版本追溯及联调检查

查询当前有效结果时附 `costRunId`、`version`、源实际日和 `sourceChanged`，已变化的依据按第 4.4 节屏蔽当前最终金额。查询指定历史运行时以 `history=true` 和 `asOf` 返回其已保存数值、质量和价格快照，一期日表或小时表随后刷新不会改写这份历史。更正后的新运行关联旧运行，K02 展示成本差额与原来源。发生影响重算时，数量源事实与库存流水仍按原业务事件追溯。

联调应覆盖来源缺失、部分覆盖及明确零的三种显示，按同日 A3/B4/公共3 分摊一千 kWh 的守恒关系，普通新价与原错价更正的历史区别，铜杆全部在库量均价及公共成品自由份额均价，以及正常、库存满足、不足、取消和减量后的利润门槛。运行重复请求和失败重试应核对有效结果发布次数及旧版本可查，成本补算前后实物量和数量流水次数保持对应原事实。

## 7. 生产记录日完整性依赖

统计页通过生产记录 S2-R18 读取对应车间日状态，日分摊和订单成本缺项可链接到「生产记录」处理。当日录全由用户核对已经发生的投入、交接、称重和执行记录后确认。生产记录 S2-R19 的完整命令见[生产记录接口开发规范](系统二-生产记录-接口开发规范.md)。

| ID | 生产记录路径 | 本模块使用 |
| --- | --- | --- |
| S2-R18 | `GET /api/v1/production/workshops/{workshopId}/days/{actualDate}/record-status` | 读取 `version`、`sourceRevision`、`confirmedSourceRevision`、`recordsComplete`、`blockingItems`，展示实际日未录全或确认后又有变更的原因。 |
| S2-R19 | `POST /api/v1/production/workshops/{workshopId}/days/{actualDate}/record-completions` | 经办人在生产记录中按当前版本及日源修订确认录全。完整性证据保存后可触发有关能源分摊和成本重算。 |

尚无日状态行时 S2-R18 返回版本与日源修订零、`confirmedSourceRevision=null`、`recordsComplete=false`。已有源事实的日期升级初始化必须按事实建立或计算当前源修订，并保留未确认状态。R19 原子核对 `expectedVersion` 和 `expectedSourceRevision`，保存已确认源修订与经办人、时间。成功后实际新增或更正使相关原、新业务日的源修订变化，旧确认不再证明当前事实完整。正产量日缺录全确认时只显示已知合格量，不能以日期已过或所有已知任务完成替代确认。车间二明确全天无产出仍采用 R14 的有效全车间日零产出证据。
