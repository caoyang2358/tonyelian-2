# 系统二 · 订单与计划开发任务与验收

本文件用于拆分前后端任务、安排联调和签收结果。接口编号沿用[订单、库存、排产与交付接口清单](api/订单库存排产接口清单.md)及[生产、能源与成本接口清单](api/生产能源成本接口清单.md)。业务验收对照[需求基线第 17 节](需求基线.md#171-核心验收场景)，页面路径和持久化方案见[开发指南](系统二-订单与计划-开发指南.md)。

## 1. 任务及依赖

| 任务 | 前端交付 | 后端交付和接口 | 依赖与完成条件 |
| --- | --- | --- | --- |
| 1. 工程与公用契约 | 复用现有门户和 API 客户端，统一吨数、金额、日期、分页、缺项与错误展示 | 验证空库和已有开发库上的迁移，复用统一响应、变更历史、幂等和整数版本，建立二期库存服务的测试入口 | 依据 V2、V4–V6 和数据设计。先跑通环境与公共接口约定，确定前后端共享标识及版本字段 |
| 2. 物料与库存基础 | 模块内物料、库存余额、期初、到货与流水。三类物料分组，展示实物、预留和可用，明确缺项与未知成本 | S2-I01–I12。固定铜板与 Φ8 铜杆身份，维护铜丝规格，以单一服务写数量流水和余额，同事务登记期初与到货，根据更正前后差额更新 | 任务 1。先交付物料查询、建规格、库存读取和期初登记，再接到货及更正，作为订单与计划的前置能力 |
| 3. 订单基本操作 | 从「订单与计划」默认打开订单列表。交付新建、详情、筛选、改期、优先级与金额确认，三个业务结果分列。单单评估从详情发起，多单联合评估由列表勾选发起 | S2-O01–O05、O09。实现订单编号唯一、物料类型约束、范围与版本返回，保存订单、改期和改优先级分别处理 | 任务 1 及任务 2 的物料定义。建单保存成功即可查到订单，评估由用户另行触发。单单和多单共用任务 7 的评估契约 |
| 4. 产能与手工日计划 | 展示两个车间普通及特殊日产能、限制原因和受影响任务。提供手工草稿、日期任务表、同日顺序、成品分配及保存冲突处理 | S2-C01–C05、P02–P07、I13–I14。读取上下文和已生效计划，一处命令同时确认任务、替换关系、库存预留、成品归属及供料承诺 | 任务 1–3。先走通一次确认及查询。保存校验和重排逻辑供任务 7 共用 |
| 5. 实际生产接入 | 「生产记录」读取同一任务 ID。先交付铜板投料和 Φ8 铜杆称重，再交付铜杆交接、铜丝称重和订单生产事实回显 | 生产模块首轮交付 S2-R01/R02、R07、R09。按一次业务事实写入统一库存服务，并回查跨车间供料兑现。随后接入 R10/R12，补齐 R03–R06、R08、R11、R13–R16 的查询、更正和结束 | 任务 2 和 4。第一轮验收投料及实际称重入库，其余执行接口按本表继续联调 |
| 6. 成品分配与交付 | 在订单详情展示归属、可交、已交与差额。提供后续分配、更正、单次或分批实际交付 | S2-D01–D07。分配复用成品归属与预留服务，实际交付原子保存事实、明细、出库、预留核销及成本引用 | 任务 2–4。可用独立开发库的同规格成品先联调，生产直接归属与任务 5 联调 |
| 7. 自动评估与两车间联合排产 | 从详情或列表显式提交评估，展示缺口、建议和受影响订单。建议与人工调整进入同一草稿，保存仍使用同一动作 | S2-P01 复用 P02、P06 的范围和库存/产能口径。成品先匹配，按用料日期扣减有效供料和现货，补排净新增铜杆及其铜板。统筹未开始需求，保留实际保护及窗口外依赖 | 任务 4 的人工闭环通过，使用任务 5 验证未来供料可兑现。评估和浏览草稿期间无正式占用 |
| 8. 订单变更及核算衔接 | 交付改量、取消、影响预览、历史，显示变更后生产、交付及核算结果。订单详情链接核算记录 | S2-O06–O08、O10。保护实际及共用份额，成品转公库复用分配服务。与生产模块 S2-R15/R16、核算模块 S2-K01–K06 核对缺项、历史成本来源及更正 | 任务 4–6 及核算共用服务。先验收数量链路并明确成本缺项，金额完整与估算盈亏由跨模块测试签收 |

可并行交付订单页面、库存页面和产能页面。以接口清单确定共同字段，先接开发环境的真实二期 API。生产与计划联调通过相同的 `taskId`，成品归属对齐 `allocationId` 和对应预留。共用事务按[数据与事务设计](系统二-订单与计划-数据与事务设计.md)实现后，再执行并发验收。

## 3. 第一条贯通场景

手工草稿先贯通，接入自动评估后用相同数据从订单详情再走一遍。单单评估和列表联合评估分别检查触发路径。

| 步骤与接口 | 可验收结果 |
| --- | --- |
| 1. 通过订单列表新建 A，S2-O02 保存后用 O01/O03 查询 | 页面可查到 A，金额显示待补。无评估请求、无已生效任务、无预留。改动仅为订单及其关联的保存记录 |
| 2. 读取 S2-P02 并手排两车间，自动评估完成后从详情显式调用 P01 | 草稿展示成品可用 0.000、用杆总需 10.000、现货 4.000、净新增杆 6.000 和计划铜板 6.300 吨。P03、I04、I13 查询的正式任务和库存均无新增占用。用原版本继续编辑 |
| 3. S2-P06 确认一次，回查 P03/P05、I04/I13/I14、R02 | 同一次确认生成两车间任务，铜板实物 20.000、预留 6.300、可用 13.700 吨，Φ8 杆实物 4.000、预留 4.000、可用 0.000 吨。另有 6.000 吨尚未兑现的供料承诺，挂在正确供需任务上。生产视图使用同一组任务 ID |
| 4. 车间一通过 S2-R07 实际投料 6.300 吨，再用 R09 分两次记合格铜杆 2.000 与 4.000 吨 | 铜板实物 13.700 吨且相关预留清零，一次投料只有一笔铜板出库。杆入库流水各一次，累计实际 6.000 吨，总实物为 10.000 吨，已兑现供料为 6.000 吨。成本缺项保留并可查，库存数量照常保存 |
| 5. 车间二用 S2-R10 交出并接收 10.000 吨，用 R12 称重铜丝 A 8.000 吨，全部归 A 订单 | 杆实物为 0.000 吨，对应预留核销。成品 A 实物与本单预留各 8.000 吨，可用 0.000 吨。归属和预留引用同一份数量，S2-D04 反馈本单可交 8.000 吨。订单生产量来自称重 |
| 6. S2-R16 登记正常生产结束，再用 S2-D06 分次交付 3.000 与 5.000 吨 | 第一次后已交 3.000、实物 5.000、本单剩余预留 5.000 吨。第二次后已交 8.000、实物 0.000、预留 0.000 吨，交付记录两笔可追溯。订单同时展示生产结束、足额交付和核算中 |

第一轮交付签收核对步骤 1–4，包括在真实开发 MySQL 上的计划写入、库存预留、实际入库和失败回滚。步骤 5–6 随生产和交付能力接入后签收。记录每步的接口结果、变更前后值及任务/库存流水 ID，页面和库表均需能核对。

## 5. 失败、重试与并发

| 复现方法 | 验收信号 |

| 在有旧计划的情况下编辑草稿后退出，比较退出前后 S2-P03/P04、I04/I13 | 原有效计划及预留版本保持。无新的生效计划和库存流水。提交成功后关闭页面，已保存结果仍可查询。对应 AC27、AC29 |

## 6. 交付验收记录

1. 开发验收记录提交版本、数据库迁移版本、夹具和复现日期、接口请求标识、结果及对应的任务、预留、流水、交付记录 ID。前端保存实际页面路径和冲突回显，后端保留服务检查与事务测试结果。
2. 模拟订单、产能、库存、金额、称重和预期供料只用于隔离开发库。用于交付演示时明确标识其来源。业务单据留存与清理由开发库快照及夹具管理，生产验收使用现场确认的资料。
3. 现场验收分别核对共享 MySQL 实际结构和车间编码映射、现场铜丝规格、真实期初台账与成本依据、可排日期和日产能、真实称重和交付凭据，以及统计使用的电、水、煤气计量覆盖。缺少资料时核查对应待补/待核算展示。以实际记录核对交接和各库存余额，统计口径随现场证据签收。来源与责任参见[数据来源说明](数据来源说明.md)。
4. 生产、库存、交付与成本的组合结果按各自证据签收。待补的外部数据、待实现的接口、已复现的缺陷分别登记，标明对应验收场景及复验条件。
