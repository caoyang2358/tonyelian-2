# 系统二 · 生产记录数据与事务设计

本文为开发设计。以[需求基线](需求基线.md)第 8、9、11 节、[生产能源成本接口清单](api/生产能源成本接口清单.md)及[订单与计划事务约定](系统二-订单与计划-数据与事务设计.md)为依据。V4、V5 已提供计划、库存和生产事实的表结构。下文标明计划外补录及多任务归属拟使用的新增结构。

## 1. 现有事实及读写映射

| 操作 | 物理依据 | 记录粒度及影响 |
| --- | --- | --- |
| S2-R01/R02 任务及实际详情 | V4 `p2_plan_task`、`p2_task_order` 及 V5 各事实表 | 任务身份为 `task_id`。计划量、计划日来自原任务，实际时间、重量和差额按事实投影。计划外实际出现在实际记录列表。 |
| S2-R03/R04 实际列表及详情 | V5 原始事实及 V2/V9 `p2_change_log` | 以记录类型和事实 ID 标识单条记录。保留实际业务日、录入时间、来源、当前版本、原始事实和更正链。 |
| S2-R05/R06 执行及更正 | `p2_output_record` 的 `EXECUTION` 行 | 实际起止落在 `started_at`、`stopped_at`。任务状态及版本仍落在 `p2_plan_task`。仅录执行事实时无数量流水。 |
| S2-R07/R08 投料及更正 | `p2_plate_input`、`p2_stock_movement`、`p2_stock_reservation` | 车间一每次实际投入一条独立事实，保留本次铜板投入吨数及可空材料总金额。正常登记时按投入量扣减实物及适用预留一次。 |
| S2-R09/R12 铜杆、铜丝称重 | `p2_output_record` 的 `QUALIFIED_OUTPUT` 行、`p2_stock_movement`，铜丝另关联 `p2_finished_allocation` | 对外类型按实际产品区分 `ROD_OUTPUT` 和 `WIRE_OUTPUT`。每次实际同规格新增称重一条事实，对应一笔入库。铜杆入通用 Φ8 库存，铜丝按规格入库并形成有效订单归属及公共差额。 |
| S2-R10/R11 铜杆交接及更正 | `p2_rod_handover`、`p2_stock_movement`、`p2_stock_reservation` | 同一交接保存交出量与接收量，实际扣库以交出量为准。接收待补时接收量和误差率为空。后续在同一记录补接收。 |
| S2-R13 产出更正 | 原始称重、关联任务数量、成品归属与原库存流水，或原 `NO_OUTPUT` 行 | 更正称重时保留原 ID 并按实际差额处理。零确认录错时保留原行，作废当前确认并记录依据。 |
| S2-R14 明确无合格产出 | `p2_output_record` 的 `NO_OUTPUT` 行 | 保存实际日期和确认的车间或任务范围，明确零量。停止执行或缺称重仍显示待统计。 |
| S2-R15/R16 任务与订单实际结束 | `p2_plan_task`、执行事实及 `p2_customer_order` | 任务停止保留计划量及差额。订单的正常或不足量结束写生产结果及原因，交付和核算分别更新。 |
| S2-R17 计划外生产补录 | 生产归集组、复用的 V5 实际事实及库存和归属表 | 有真实事实时创建或引用计划外归集组。独立的实际记录与实际日期支撑后续查询、补录、统计和更正。 |
| S2-R18/R19 日录全状态与确认 | 拟新增 `p2_production_day_status`，事实仍来自 V5 及其增量扩展 | 按车间、实际日保存来源修订和已确认修订。事实写入或更正同事务使确认失效，确认不产生库存数量流水。 |

## 2. 计划外归集组及增量迁移

拟在开发时新增 `p2_production_group`。保存 `production_group_id`、`origin`、`workshop_id`、`material_id`、`anchor_actual_date`、`operator_name`、`reason`、`recorded_at` 和 `version`。车间与产品关联现有字典和 `p2_material`。`origin` 取 `PLANNED`、`UNPLANNED`。车间一产品为 Φ8 铜杆，车间二为一个铜丝规格。归集组是同一实际过程的关联身份，实际库存流水和统计仍以事实为单位。

S2-R17 `POST /api/v1/production/unplanned-records` 首次提交携带组范围和一条有明确类型的事实。服务端核对车间、产品、实际日期、经办人及原因，在同一事务创建 `UNPLANNED` 组、登记首笔事实并同步必要的库存及归属。`anchorActualDate` 为首笔登记事实的实际日，供查找和追溯。后续携带 `productionGroupId` 和组 `expectedVersion` 追加事实，每条事实保存自己的 `actualDate`。跨日统计按事实日期归属。组范围不可借追加事实改写，保存成功后更新组版本。

一个 R17 请求登记一个执行、投料、交接、铜杆称重或铜丝称重事实。关联执行或归集依据随命令校验，称重所带成品归属和库存变动在同事务生效。已有计划任务的补录沿用原任务的生产接口，即使实际日期偏离计划日。无任务的补录保持计划任务关联为空。零产出确认仍由 S2-R14 写入。

| V5 现状与缺口 | 拟在新增 Flyway 迁移中落实 |
| --- | --- |
| `p2_plate_input.task_id` 和 `p2_rod_handover.task_id` 必填 | 将这两个字段改为可空，新增可空的 `production_group_id` 外键及索引，并约束必须有真实任务或归集组。服务端核对组来源与任务关系。 |
| `p2_output_record` 的执行记录必须有任务。合格产出可以仅带现有 `production_group_key` | 新增 `production_group_id` 外键，扩展执行与合格产出分支校验。保留既有字符串归集键及已允许的历史记录读法。新写入使用已核验的任务或归集组。 |
| `p2_rod_handover` 通过任务派生车间，现有时间依靠 `sent_at`、`received_at` | 新增归集组外键后可沿组取得计划外车间、规格。交出时点对应一次真实领用，交出业务日由 `sent_at` 在 `Asia/Shanghai` 的日期表达，校验 API `actualDate` 一致。次日接收保留真实时间。 |
| 投入及执行关联存为 `input_references`、`execution_references`，任务关联只有 V5 的 JSON 与主任务列 | 沿用真实投入与执行事实 ID 引用，带上同组、车间、任务及产品交叉校验。合并称重的任务数量另见第 3 节的明细设计。 |
| V5 `NO_OUTPUT` 行缺少保留原记录的作废标记 | 拟在 `p2_output_record` 增加可空的 `voided_at`，限 `NO_OUTPUT` 行填写。有效日期及任务统计排除已作废记录，实际详情返回其原状态及更正审计。 |

原 V5 迁移保持原样。新增迁移版本在落实时接续最新编号。已有计划内事实仍按原任务读取，可在有明确来源时补充归集组。历史仅有关联键的记录继续显示其原始依据，迁移时不推断计划外来源或组内数量。

## 3. 称重、任务和订单归属

车间二每次换单停机后按真实称重分别登记。日末合计读取当天的新增称重。一次确实跨多个任务的称重仍只生成一个 `output_id` 和一笔入库流水，保留原总量。对有计划的单任务称重，V5 的 `task_id` 足以定位。计划外称重按归集组关联，可以携带真实订单分配。

确实跨任务的共用称重拟通过 `p2_output_task_share` 存储 `output_id`、`task_id`、`qualified_quantity_ton`，以产出 ID 和任务 ID 为唯一键。已明确的任务份额按实测依据记录，份额之和不得超过原称重总量，完整分配时须相等。份额待补时保留整笔称重和已知部分，未归到任务的重量在任务明细提示待补。任务查询使用份额，车间日汇总按不同 `output_id` 汇总原始称重。任务引用与份额同时存在时使用份额作为该任务实际量。

订单归属以同规格成品的 `p2_finished_allocation` 为准。分配合计不得超过称重总量和各订单可归属份额，公共量等于总量减本次订单归属。多任务称重如需在明细同时追溯归属对应的任务，拟为 `DIRECT_OUTPUT` 分配保存可空 `attributed_task_id` 外键，并核对其属于同一称重的任务及数量边界。对计划外实际，订单归属由称重和分配关联追溯，任务字段为空。已有成品后分配和交付在各自权威入口更改，统计以来源去重。

一笔铜板投入可被多次铜杆称重引用，材料总金额按投入 ID 归集一次。领杆交接可以通过 V5 `receiving_references` 保留可核对的接收任务、订单和数量份额。明细不全时保留交出总量、已知份额及缺项。总库存按交出量变动一次，后补接收不增加出库。交接误差以交出量为分母，正负偏差均按绝对值计算。超过 5% 时须记录放行原因、人员和时间。

车间二分次或跨日产出还需要将每次称重与实际领杆成本份额对应。R12、R17 的铜丝称重及 R13 更正携带 `rodUseReferences`，包含真实 `handoverId` 和本次对应的 `sentQuantityTon`。存储采用 V5 `input_references` 的类型化引用，映射及锁内校验见[统计数据与计算设计](系统二-生产与能源统计-数据与计算设计.md)。同一交出数量不能被多笔产出重复使用。唯一明确的适用来源允许服务端推导并返回依据；来源不明时保留真实称重和缺项，不能仅因同任务或同归集就复制整笔领杆成本。补齐引用只推进来源与成本修订，不重复扣铜杆库存。

## 4. 共享库存、锁顺序与幂等

生产以真实事实驱动实物。铜板投料与交出铜杆扣实物，合格称重入实物，接收补录和执行起止各自更新事实。计划内生产在可用范围内核销本需求预留。Φ8 铜杆实际入库可兑现相应有效供料承诺，再依规则形成现货预留。计划外生产使用公共可用份额和实际来源，订单归属成品形成对应交付预留。排产预留、日计划或未来供料的新增与重排继续走 S2-P06。实际引起订单剩余加工量变化时，更新加工范围版本并提示受影响的已确认安排。

生产服务沿用订单与计划的锁层级。先占全局 `p2_request_result.request_id`，依次锁相关订单、车间产能根行及日期设置、相关物料与库存余额，再锁既有方案、任务、预留、供料承诺、成品归属、交付、原始流水与生产事实。生产归集组在生产事实层中先于其明细加锁。按同类主键升序，对变更实际日期涉及的旧日和新日均复核。持锁后重新读取受影响范围，发现需要补锁更早层级对象时回滚并重新收集或返回冲突。

车间根锁同时协调事实登记、跨日更正与整日零产出确认。S2-R14 在持锁后检查同日所有计划内外有效称重及同范围有效零确认。任务范围的零确认核对该任务的实际份额。已有共用称重关联该任务而份额未明确时，先补齐明细再确认。车间整日已确认零后再发现正产量，先按 S2-R13 持同一车间根锁作废误录，再按实际日期补录称重。缺称重、存在部分事实和确认零分别投影。车间根锁也用于协调真实执行区间的交叉检查，允许未知的起止端按待补处理。

幂等摘要覆盖操作、目标路径与稳定序列化的命令内容。已有同号同内容的成功请求直接返回保存结果，包括组 ID、记录 ID 和库存版本。换组或改变输入仍复用同号时返回冲突。业务、库存、审计和幂等结果同事务提交。失败时回滚组创建、事实、流水、余额、预留及请求占位。库存流水的来源唯一键用于防止同一原始事实重复入账。事实及业务聚合版本沿用非负整数。

## 5. 更正、完成及验收

- 沿用 S2-R06/R08/R11/R13 的真实类型和原事实 ID 更正计划内外记录。锁内核对原事实版本，保存前后值、原因、人员和录入时间。存在归集组时同事务推进组版本，使旧追加草稿能发现变化。归集组首录依据留存，统计采用更正后的有效实际日期。
- S2-R13 可对有效 `NO_OUTPUT` 行提交 `changes` 中的 `voided=true`。按原事实版本校验，填写作废时间、推进版本并写入更正审计。原零记录继续可查，作废当次没有库存写入。之后正产出补录仍按有效事实重新校验。
- 原数量更新仅按差额过账并引用原库存流水。只补材料金额、接收量或说明时库存保持原扣增结果。更改实际日时明确原日与新日及相应库存历史和成本归属影响。冲突涉及下游领用、其他预留或已交付份额时返回对象和原因，事实与库存同事务回滚。
- 有实际开始、投入、领用或称重的任务保留其计划目标。任务实际停止可以先登记，缺称重仍待统计。订单已结束或取消后允许如实补记历史发生事实，保留原结案与审计关系。取消后新登记的历史事实按取消单规则处理可再用未交付成品及成本。合同金额确认由 S2-O09 管理，生产登记可保存缺金额或缺成本的实际。
- 隔离库验收需覆盖首次计划外补录成功及失败回滚、同组跨日事实、旧组版本及同号并发回放、重复库存来源、换单两笔实测、同次合并称重的任务份额、计划内外实际与整日零产出竞争，以及有下游领用或交付时的冲突。另核对订单 A 的 2 吨计划外铜丝只入库一次，订单实际和归属随之更新，并可由实际记录追溯源头。

## 6. 日录全确认及失效

本轮用户确认新增按车间日的记录完整性声明，S2-R18/R19 见[接口开发规范](系统二-生产记录-接口开发规范.md)。日状态表字段、来源修订与核算发布设计见[统计数据与计算设计](系统二-生产与能源统计-数据与计算设计.md)。迁移接续最新编号，保留 V5/V6。GET 无日根行时只返回初始版本及未确认状态，不能在查询时插行。

共享车间根锁协调日状态首次建立、R19 和所有事实写入。日根位于车间根后的同类日期锁层级，按车间、日期稳定排序，之后再进入物料、任务和事实等既定锁层。涉及跨日的更正一次收集旧新两日。持锁重新读取事实和版本，确认时核对 `expectedVersion` 与 `expectedSourceRevision`；写入事实时递增受影响日的来源修订，并使原确认失效。确认和事实谁先提交都可得到一致结果，零确认与正产出的竞争仍按既有车间锁校验。

日确认检查已经发生但缺称重或必要分母依据的阻塞项，缺材料金额、能源价格等列成本缺项。未发生的计划不生成实际。未来日不能确认；零产出日要求有效整日零事实。确认保存审计和幂等结果，更新已确认来源修订，并可靠触发核算，不执行数量入出库。所有计划内外新增、更正、作废、实际日调整及来源份额补齐共用失效逻辑。生产事实、库存、来源修订、失效审计和核算触发标记同事务提交。
