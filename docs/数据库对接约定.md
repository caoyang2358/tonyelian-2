本次还观察到MySQL80服务运行，但没有登录数据库、查询实际版本/表字段，也没有启动或重启一期后端。历史日志证明当时的连接，不等于本次完成了当前连接测试。

二期表设计应以实际MySQL结构核对为准。随后已静态核对MySQL部署版V1建表及V2、V3，下列逻辑表清单也与这些MySQL源文件对照；这仍不等于查询了现用库。二期独立开发，不继承后端2代码或调用其API。

## 开发前需要的数据库资料

1. 实际MySQL版本及当前库结构：表、字段、主键、索引、约束和现用迁移历史表。可由负责人提供仅结构导出或在受控开发环境核对元数据。
2. 可用于开发的结构副本和脱离现用库的演示数据。每位成员创建自己的开发库。
3. 明确一期既有表的读取范围、二期新表、确需写回共享主数据的字段与唯一写入口。
4. 明确车间总表覆盖、单位、采集/统计日期及缺失数据；不能仅凭源码种子认定现场数据齐全。
5. 连接资料放各自本地配置或环境变量；协作平台只保存配置项示例。

车间使用编码 `WS-ROD` / `WS-WIRE`；设备、测点使用已有唯一编码查实际ID，不把种子数值ID写死。工序展示关系与真实设备归属分开。

## 二期自有数据与写入

- 订单、产能、日计划、库存、预留、实际投入/称重/交接、分配交付、成本归属、能源生效单价、维修知识及布局等由二期建立自有业务表。
- 建议二期自有表统一 `p2_` 前缀，同库迁移使用独立目录及历史表。业务表最终结构在后续数据设计阶段确定；本次仅落地技术元数据表p2_project_info，迁移位于backend/src/main/resources/db/migration-phase2。
- 采集值、最新值和一期能源汇总主要读取；设备/测点主数据为满足二期管理需求，可维护约定字段并保存更正记录。新增设备建议统一登记共享身份，再写二期扩展；字段范围与写入口由数据设计统一，避免重复身份及多套维护逻辑。
- 不复制执行一期PostgreSQL V1—V7，不修改一期迁移历史，不重跑清库初始化。
- 一次确认任务与预留、一次称重与入库由二期后端事务组织。二期不经一期API拼接这些事务。

## 能源和成本口径

- 指定源码的车间一电/水/煤气总表为 `EM-E-ROD` / `EM-W-ROD` / `EM-G-ROD`；车间二有 `EM-E-WIRE` / `EM-W-WIRE`，未见独立车间二煤气表种子。实际库覆盖待核实，缺失不填零、不借其他总表。
- 二期合格产量来自自己的真实称重，不读取一期能源日表的 `production_quantity` 充当订单产量，更不能按电水煤气行重复累加。
- 二期按自己的已确认单价规则核算，不直接把一期日表 `cost` 当成订单成本。
- 材料金额、能源或期初成本未齐时，真实数量仍保存，费用待核算。
