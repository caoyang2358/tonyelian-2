## 0. 使用说明

- 本清单按**六条验收任务**组织，每条拆成可在页面上直接执行、可直接判定的步骤。逐项勾选「通过 / 不通过 / 不适用」，并在备注里写证据编号。
- 判定口径：**「不适用」不等于通过**。凡是本版演示数据或当前表结构无法覆盖的场景（如订单取消、减量、候选发布对比），统一记「不适用」并写明原因，不要凭推测打勾。
- 标 ⚠️ 的步骤是**写操作**，会改动数据库。建议放在最后做，或先按 `.local/演示数据说明.md` 第三节做快照，验收完整体回滚。
- 本清单的预期数值全部取自 2026-11-19 22:10 的**真实接口响应**，不是设计值。若环境重建、数据变动，先按第 1 节复核基础数据再开始。

## 3. 接口复核命令（可直接粘贴）

后端地址 `http://127.0.0.1:18280`。日期参数是 **`from` / `to`**（不是 `startDate` / `endDate`）。

```bash
# E01 总量（六项基线）
curl "http://127.0.0.1:18280/api/v1/energy/totals?from=2026-11-19&to=2026-11-19"

# E02 日来源明细（可按 workshopId / energyType / qualityStatus / page / pageSize 筛选）
curl "http://127.0.0.1:18280/api/v1/energy/daily-consumptions?from=2026-11-19&to=2026-11-19&page=1&pageSize=20"

# E03 车间二当日分摊
curl "http://127.0.0.1:18280/api/v1/energy/workshops/2/days/2026-11-19/allocations"

# E04 价格列表与适用价匹配
curl "http://127.0.0.1:18280/api/v1/energy/prices?page=1&pageSize=20"

# E05 新增价格（写）
curl -X POST "http://127.0.0.1:18280/api/v1/energy/prices" \
  -H "Content-Type: application/json" \
  -d '{"requestId":"accept-e05-1","energyType":"ELECTRICITY","scope":"WORKSHOP","workshopId":2,"effectiveDate":"2026-11-20","unitPriceYuanPerUnit":"0.88","operatorName":"验收","reason":"验收新增"}'

# E06 更正价格（写，需原版本）
curl -X POST "http://127.0.0.1:18280/api/v1/energy/prices/{priceId}/corrections" \
  -H "Content-Type: application/json" -d '{...}'

# K01 库存成本
curl "http://127.0.0.1:18280/api/v1/costing/stocks?page=1&pageSize=20"

# K02 成本流水
curl "http://127.0.0.1:18280/api/v1/costing/stock-ledger?page=1&pageSize=20"

# K03 订单核算列表
curl "http://127.0.0.1:18280/api/v1/costing/orders?page=1&pageSize=5"

# K04 订单核算依据（订单主键 9302 / 9303）
curl "http://127.0.0.1:18280/api/v1/costing/orders/9302"

# K05 触发补算（写）
curl -X POST "http://127.0.0.1:18280/api/v1/costing/recalculations" \
  -H "Content-Type: application/json" \
  -d '{"requestId":"accept-k05-1","operatorName":"验收","reason":"验收补算"}'

# K06 运行查询
```
