# 隔离开发空库快照

本目录只供**全新、空白、与一期或现场环境隔离的本机开发库**使用。它不是一期升级脚本，不是生产 Flyway 迁移，也不用于覆盖、刷新或清理已有数据库。SQL 文件不创建或切换数据库；调用方必须事先选定正确的隔离空库。

## 文件与执行顺序

1. `001_phase1_schema_snapshot.sql`：从当前“后端2”的 `src/main/resources/db/migration-mysql/V1__mysql_schema.sql` 提取原有 12 个 `CREATE TABLE` 及 3 个补充外键的 `ALTER TABLE ... ADD CONSTRAINT`。表结构保持原样，文件头记录源文件 SHA-256。已移除源文件中的删表及关闭外键检查操作。
2. `002_demo_metadata_seed.sql`：仅写入 2 个车间、8 台生产设备、10 个已知工艺传感器、10 个参数定义及 7 种对应单位。必须先完成步骤 1，再在同一个新空库执行本文件一次。
3. 二期独立迁移由项目启动脚本按 `../migrations/` 的正式约定执行；本目录不替代迁移版本管理，也不写入一期 Flyway 历史。

不要重复导入。既有同名表或相同业务编码应使导入失败，避免悄悄改写已有资料。开发库重建及实例管理由外部开发脚本负责，本目录不包含重置或删除脚本。

## 演示元数据边界

- 车间、设备及传感器编码和归属沿用一期 V2 的静态定义。它们是开发演示资料，尚不代表现场核验完成；车间说明及传感器 `data_source = DEV_DEMO_METADATA` 明确标识了这一点。
- 责任人等未知资料留空。正常/报警阈值、采样周期及工序关联不伪造，由后续配置及核对补齐。已有传感器标识及设备归属不因组网显示不同而改动，尤其 `TEMP-003`、`LEVEL-001` 仍归属 `SMELT-FUR-01`。
- 不写入传感器实测或最新值、能源用量、能源价格、能源表计、订单、生产事实、期初物料或成品库存，也不会启动模拟采集。无数据不能被解释为现场实际数值为零。
- 不填成品库存，符合第一版初始默认无成品的要求。已有铜板、铜杆及铜杆成本应由二期实际初始化流程人工登记。
- 当前一期已知缺少车间二独立煤气总表。本演示种子不补造煤气表或其他来源。

**版本口径**：本快照取自 `bea8047f…`，即当时 `local-deployment/Start-Local.ps1` 实际加载的那份部署源码；而《需求基线》《当前开发约定》《数据库对接约定》指定的基线是 `b8f1231c…`。两者差异**尚未比对**，不能把本快照称为「指定基线的结构」。需要对齐时，应重新取得 `b8f1231c` 的 `V1__mysql_schema.sql`，按文件头记录的 SHA-256 方式重新校验。

**未进入本仓库的内容**：一期源码本身（含 V2 元数据脚本）从未提交到本仓库任何分支。`002` 中的设备与测点编码是人工摘录，只保留了一条来源注释，没有原始文件副本与校验值；要核对全量与一致性，需重新取得一期源码或接入一期只读库。

此快照为 MySQL 语法，原始一期声明兼容 MySQL 5.7+。MySQL 5.7 不实际执行 `CHECK` 约束，数值及状态校验仍须由应用完成。使用该脚本不表示本次已连接或验证任何数据库；建库和执行由本机隔离开发启动流程负责。
